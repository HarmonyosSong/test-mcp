# Public knowledge contract

This directory is a checked-in copy of the public contract bundle from the upstream `dev-knowledge` repository; see [UPSTREAM.md](UPSTREAM.md) for its pinned commit. The upstream service owns the authoritative response definitions. `mcp-responses.schema.json` exports the two public tool response schemas (`wiki_resolve` and `wiki_read`) in `properties` with shared `$defs`. `examples/*.json` contains synthetic response cases with `tool`, `arguments`, `expected_outcome`, and `response`. `manifest.json` carries a contract version and SHA-256 for every schema/example file.

Schema and manifest generation happen upstream. When the upstream contract changes, update this copied bundle from the reviewed upstream revision and refresh its manifest; do not edit the generated schema by hand. Mastra consumes this bundle from `runtime/contracts/dev-knowledge/`. A separate compatibility copy remains under the retired Python Agent source for historical review; it is not an active consumer and does not need to be updated for product runtime operation. The active consumer validates identities, requested scope, truncation and source closure without importing server internals.

Run `make test-runtime` for the current Mastra consumer; its tests verify the runtime bundle against its integrity manifest and exercise the fixtures. The retired Python copy and tests are retained as historical references; the old Python projects are no longer packaged or supported. The samples cover full code/document citations, normal/missing results, truncation, invalid requests and oversized responses. Global catalog queries remain an explicit service capability; the active Mastra consumer applies its authorized query scope.

Document locators may include `document_source` with required `source_id`, `document_id`, `role` (`product`, `technical`, or `reference`), nullable declared `version`, and the original file `content_sha256`. Existing locators without this object remain valid; explicit null is rejected. The document reference key hashes the entire locator, including provenance when present, so changed versions or bytes receive distinct references. `wiki-read-ok` demonstrates provenance and `wiki-read-truncated` retains the older absent-field shape.
