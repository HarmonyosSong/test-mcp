# Public knowledge contract

This directory is a checked-in copy of the public contract bundle from the upstream `dev-knowledge` repository; see [UPSTREAM.md](UPSTREAM.md) for its pinned commit. The upstream service owns the authoritative response definitions. `mcp-responses.schema.json` exports the two public tool response schemas (`wiki_resolve` and `wiki_read`) in `properties` with shared `$defs`. `examples/*.json` contains synthetic response cases with `tool`, `arguments`, `expected_outcome`, and `response`. `manifest.json` carries a contract version and SHA-256 for every schema/example file.

Schema and manifest generation happen upstream. When the upstream contract changes, update the current Mastra bundle at `runtime/contracts/dev-knowledge/` from the reviewed upstream revision and refresh its manifest; do not edit generated schemas by hand. This directory is retained only as a legacy Python adapter reference; it is no longer an active consumer. For current product maintenance, use the Mastra bundle and `make test-runtime`. The active consumer validates identities, requested scope, truncation and source closure without importing server internals.

Run `make test-runtime` for the current Mastra consumer; it verifies the runtime bundle against its integrity manifest and exercises the fixtures. The Python adapter and fixtures below are historical migration references; the retired Python runtime has no supported test command. The samples cover full code/document citations, normal/missing results, truncation, invalid requests and oversized responses. Global catalog queries remain an explicit service capability; the active consumer applies its authorized query scope.

Document locators may include `document_source` with required `source_id`, `document_id`, `role` (`product`, `technical`, or `reference`), nullable declared `version`, and the original file `content_sha256`. Existing locators without this object remain valid; explicit null is rejected. The document reference key hashes the entire locator, including provenance when present, so changed versions or bytes receive distinct references. `wiki-read-ok` demonstrates provenance and `wiki-read-truncated` retains the older absent-field shape.
