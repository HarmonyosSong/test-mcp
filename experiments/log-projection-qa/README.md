# 日志结果投影 QA 实验（2026-11-23）

背景：日志工具返回的 JSON 是轮内上下文体积的最大来源（93801fc 实测单次 106K 字符 ≈ 86K token）。
本实验验证「JSON → Markdown 表格投影」在**不减损模型读取质量**的前提下能省多少输入，
其结论直接支持 `runtime/src/diagnosis/log-projection.ts` 的工程化。

## 方法

- fixture（`projector_v3.py` 内生成，随机种子固定）：按 `.data` 真实 `search_both_logs` 返回形状
  建模的聚合日志——日志中心 8 组 × 6 条 + 云日志 20 组 × 5 条，每条 18 个扁平字段，
  含中文 msg、重复会话/设备上下文、重复 stack；JSON 序列化 153,054 字符（对齐 106K 真实事故量级）。
- 投影器 v3（同文件）：恒等字段提升到组头公共块、诊断关键列（ts/level/clickid/msg/traceId）
  白名单保留、重复 stack 去重编号引用、无频率截断、无内容摘要。
- 测量：deepseek API `usage.prompt_tokens`（精确 tokenizer 计数，非估算）。
- 质量：5 种题型 × 每形态 3 次重复（`qa_experiment.py`，判分用 fixture 里算出的确定性答案）：
  双字段计数（17）、eventId→traceId 定位、level 分布聚合、最早 ts、分组条数。

## 结果

| 形态 | 字符 | prompt tokens | QA 正确率（15 次） | 平均推理 tokens |
| --- | --- | --- | --- | --- |
| 原始 JSON | 153,054 | 65,173 | 15/15 | 2,202 |
| 投影 v3 | 90,072（-41%） | 40,139（**-38%**） | 15/15 | 1,613（-27%） |

逐次明细见 `results.json`。投影样例见 `projection_sample.md`。

## 保真审计

`projector_v3.py` 的投影对 fixture 做逐字段核对：2,664/2,664 个键值对在投影文本中
原样可找回、148 行守恒、stack 引用无悬空。工程版在 `runtime/test/log-projection.test.ts`
内置了同样的审计用例（含嵌套值、竖线/换行转义还原）。

## 失败记录（v2，重要教训）

中间版本按频率选列并截断到 10 列，**静默丢掉了 level/traceId**：
token 更省（36,722）但模型在计数题上烧光 8,000 推理 token 也答不出来——
它在推理中反复尝试「推断」缺失字段。由此定下投影器铁律：字段零丢弃、
关键列白名单、任何省略必须显式标注并给出再取方式。

## 边界与未验证项

- fixture 是平铺字符串字典形状；真实返回若含深层嵌套，工程版按 JSON 内联处理（已测可找回）。
- 题型是抽取式（计数/定位/聚合），不是完整诊断任务；端到端收益以 live-eval 与生产观察为准。
- QA 每题每形态 3 次重复，共 30 次调用；样本量支撑「投影不减损读取」的结论，
  不代表覆盖所有日志形状与提问方式。
