### 4.1 分开看上传与入口

新预览策略在旧整体样本有收益，但没有改善这组上传问题，不能外推为“预览问题已经解决”。
唯一库外误召回是公司报销系统上传发票 PDF，三种配置均命中本产品发票知识。

### 4.2 可以复现的排序原因

查询：“鸿蒙错题本能选到PDF，这代表业务允许录入PDF吗”。

V2 实际特征：objects=`[error-book]`，actions=`[]`，facets=`[]`。
将诊断探针的 limit 扩到 10 后可见完整相关顺序（正式 lookup 仍只返回前三）：

| 顺序 | 候选 | 分数 |
|---|---|---:|
| 1 | error-book-unavailable：入口不可用 | 0.55 |
| 2 | error-book-upload-fails：上传失败现象 | 0.55 |
| 3 | error-book-entry-picai-only：入口资格 | 0.55 |
| 4 | **error-book-upload-file-types：上传格式事实** | **0.55** |

“PDF、录入、上传、图片、数量”没有为本组候选提供足够的区分特征，
同分排序按现象优先及 ID 决定，上传事实落到第四。预览又选了入口现象、入口事实和上传现象，
关键格式正文没有返回。引用图能通向它，但 Agent 必须识别遗漏再额外读取，不能计作已获得判据。

查询：“错题录入选了PDF，点完成后回到了应用首页”。三种配置都没有候选。
“错题录入”不等同于当前已登记的“错题本/错题集”等对象表达，这是词表/别名覆盖缺口。

另外两条缺产品信息的歧义问题：“选择PDF点完成后返回首页”“上传图片失败了”。
legacy 返回错题上传相关条目，V2 拒绝命中。由于用户未指明产品，
这两项不并入正负例准确率；它们用于提示 Agent 不应把相似症状直接解释为错题本。

## 5. 内容层检查：比机器校验多出的限制

### 5.1 有来源的规则不等于当前故障根因

`error-book-upload-file-types` 写了“能选到 PDF 即容器未收敛，已成立”，
同时例外又说明业务规则来自 2024-12，后续版本未逐一核对。
针对被核实的特定代码路径，可以陈述未设置过滤参数；
但把“任何工单能选 PDF”直接推到该机制，会略过实际容器、页面 accept、线上 H5 版本的核对。
更不能由此证明“返回首页”的因果链。本轮没有访问知音楼重新核验文档，日期与权威按文件元数据报告。

建议将“历史产品规则”“指定 commit 的实现事实”“本次工单候选”明确分开写，
增加实际路径和版本适用条件；不要让一个 official 标签覆盖全部推断。
66 个事实的版本字段目前都为空，正文里的历史适用限制没有进入机器版本判断。

### 5.2 代码路径描述需要纠正

新事实把 `components/XesWebview.ets` 描述为“另一套实现”，但本地指定 commit
`6919c027f1d8d818f28454da24a37b99c149b901` 中：

- `components/XesWebview.ets:3` 导入 `./webview/WebView`。
- 同文件约 1884 行实例化 `WebView({...})`。
- `components/webview/WebView.ets:123–139` 才是本次读取到的 `openDocumentUploadPicker`。

因此这两个文件在该快照是外层与内层调用关系，不能直接当作两条独立选择器链路。
新症状让人到 `XesWebview.ets` 找 `onShowFileSelector`，也不如直接给出实际实现文件清楚。
这类锚点混淆会让 Agent 重复搜索，正好与上一轮工具浪费问题相连。

### 5.3 描述有内部不一致

新症状的 description 仍写“容器侧结论尚待代码核实”，正文注意又写“已于 2026-09-28 核实成立”。
应统一为“指定快照实现已核对，当前事件路径与回首页原因仍未确认”，
避免摘要和正文给 Agent 不同的证据状态。结构校验不会发现这种冲突。

## 6. 建议下一步

1. **先修新条目的适用条件和代码锚点**：保持稳定 ID、来源与真实验证日期，不用加权权威掩盖内容冲突。
2. **补同对象内的任务区分**：录入/上传与导出/分享、格式/大小/数量与入口资格应参与已有错题对象候选排序。
   PDF、上传等通用词只作为限定/动作，不能独立打开全库召回。
3. **用同一查询相关性评估引用正文**：已返回上传症状时，优先展示其上传判据而不是再次塞入入口资格；
   不按 ID 排序凑前三，也不默认展开所有引用。
4. **为新知识增加入库验收**：每条新事实至少覆盖自然改写、相邻意图、库外碰撞、正文可见性与规则边界。
   不能只测 canonical ID 或原样 aliases。保留本轮 16 项为开发集，另取独立真实问题验收。

这些是后续修改建议，本轮没有调词、改排名或放宽门槛来提高分数。
