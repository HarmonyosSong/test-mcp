# 非向量检索 V2 调整评测：2026-09-28

这轮修改减少了限定词和标识符碰撞，在冻结业务样本上也增加了召回。**仍不满足默认启用 V2 的条件。**
较容易独立采用的改动是 ranked 预览开关：实测 221 个问题的 legacy 候选、分数和顺序保持一致，目标正文更容易出现。
默认召回与默认 legacy 预览保持不变，没有重启服务或改运行环境。

## 1. 对照范围

- 基线：`6eed7df` 的 V2/F，见[上轮报告](REPORT-V2-FOLLOWUP-2026-09-28.md)及其归档。
- 调整：同一 HEAD 上的未提交工作区，`ENGINE_VERSION=v2-contextual-facets-1`。
  [完整结果](results-v2-adjustment-2026-09-28.json)记录实际源文件 SHA256、规则摘要、快照、环境及评测脚本摘要，不能只凭 HEAD 复现。
- 89 个条目（65 事实、24 现象）的文件摘要与基线全部一致；没有改写 aliases、判据、权威或验证日期。
- 原 153 项与新增 68 项的 ID、问题及标签均保持原样；新增集文件 SHA256 与上一轮一致。
  原 38 问已用于开发，新 68 项也是看过语料和规则后构造的压力样本，均不属于真实流量准确率或独立盲测。
- 本轮通过实际 MCP 跑 V2 与 legacy+ranked 的原 153 项，各额外跑 24 次症状描述探针；
  新 68 项通过实际 MCP 跑 legacy、V2、legacy+ranked 三组。原 legacy 153 项复用已归档基线，另用当前离线 A/B 消融核对。
- 性能对比另做五批交替顺序的串行热查询，每模式共 280 次，初始化单列；没有模型调用。

## 2. 实现变化

1. 保留匹配边界，禁止把 `合，同` 拼成合同、从 `xnoteBackupTask` 或 `foo/xnote` 内截取 XNote。
   保留条目原有的 `H5 调用原生` 有空格写法，避免边界修复反而损失已有混合语言短语。
2. 将附近、地区、弹窗、AI 搜索、腾讯会议改作限定条件。香港/澳门/台湾分开取值，不再共同占据对象覆盖率分母。
   只有查询和条目共享显式业务场景与限定值，且查询没有业务对象时，才能经 C 通路提供歧义线索。
   通用的“搜索不出来/搜不到结果”不能独立召回。
3. 单个“家长”角色不再提高某个购课事实的相关分；多个角色比较仍保留有限评分。
4. 两个检索 API 都支持当前快照中的完整规范 ID；引用相关性先检查候选资格，不能只靠总分绕过门槛。
5. 增加独立 `preview_strategy` 配置、响应和日志字段；规则摘要补入单位/角色/地域/场景与边界规则，快照纳入预览策略。
6. 修正消融脚本旧负例门槛的空集合误通过：检查实际 `negative` 分组，分组缺失也不能判为通过。

详细规则与部署开关见[设计文档第 18 节](../../docs/knowledge-retrieval-v2-design.md#18-2026-09-28-调整实现与边界)。

### 退化与代价

- “附近5km”“弹窗不显示了”现在不再命中其事实锚点，因为缺少业务场景。它们确实是库中的现有别名，
  所以必须记为自检退化，不能删除标签把指标做回去。补充“选课/教学点”或“班级”后可提供线索；
  未来需要从对话观测传入明确场景，或重新审核通用别名的预期行为。
- “家长已经撤销刷脸授权，为什么学生端还留着人脸登录按钮”目标事实从第一名后移，仍在前三且有正文。
  “忽略单一角色”的规则修复了购物车排序，却不是完整的角色语义解析。
- 原 38 问仍漏三个目标：同一 H5 的容器内容差异、体验三讲未付款调课、后续课次级联改期。
  没有添加整句评测问题到词表来填补这些缺口。
- 原六项发布指标仍是 **4 通过、2 失败**：16 个压力负例误放须 ≤4，实际 5；历史改写须 ≥3/10，实际 2/10。
  这些旧门槛还不足以覆盖本轮新增负例、事实锚点和真实诊断要求。

## 4. 独立预览改动

| 目标正文可见性 | legacy 旧预览 | legacy + ranked |
|---|---:|---:|
| 原 38 正例 | 23/38 | **29/38** |
| 新 32 正例 | 21/32 | **24/32** |
| 65 个事实别名/标题自检 | 58/65 | **63/65** |

全部 221 项逐题确认候选与排序一致。这里的收益来自正文选择，召回率没有因此变化，
legacy 的库外误命中也没有改善。68 项 × 3 模式的响应都满足最多 3 篇、每篇 1500 字符且保持 leads_only。
V2 没有发现“无资格引用标成 relevant_reference”的情况。

开启方式为保留 `HARMONY_AGENT_KNOWLEDGE_RETRIEVAL_MODE=legacy`，
另设 `HARMONY_AGENT_KNOWLEDGE_PREVIEW_STRATEGY=ranked`，再重建工具实例或重启服务。
回滚将预览策略设为 `legacy`。本轮只交付开关及验证，没有修改正在运行的服务配置。

## 5. 剩余误召回与下一步

新压力集仍有 11 个无关候选：微信手机号、淘宝购物车、咖啡店优惠券、劳动合同、宾馆发票、
银行人脸、B 站回放、抖音作品、小红书评论、高考答案、记事本个性化推荐。
其中 9 个状态为 ambiguous，2 个仍为 leads_found（淘宝购物车、抖音作品）；歧义标记不抵消误召回。

下一步应让明确的产品/业务场景参与冲突判断，并覆盖未知产品和教育产品之间的碰撞，
而不是逐个把这 11 句加入黑名单。正文局部索引和角色关系解析应另做消融，
确认它们能补漏而不会把判据中的通用词扩散成新的候选。
