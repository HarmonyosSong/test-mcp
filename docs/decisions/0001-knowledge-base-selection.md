# 0001：文档入库筛选条件

2026-09-22。这份文件是**约束**：从知音楼 PRD、工单等外部文档蒸馏知识条目时按这里筛。
不符合的不入库；符合的按对应等级标注。

## 〇、前提：知识库是代码的**索引**

默认策略是**业务现象优先查知识，明确技术线索直接查证据**。知识库把用户语言映射到业务场景、候选
链路和代码及证据位置；产品、端、版本作为已知上下文参与定位，不凭空补齐。

业务现象先检索现象条目，未命中再检索事实和术语映射；仍无有效线索时，按已有线索做有范围的代码检索
或追问。已有明确堆栈、路径、符号或接口错误时，可直接核实对应代码和证据。知识命中不等于根因成立。
完整流程与当前接入状态以 [知识库 README](../../knowledge/README.md#默认排查路径) 为准。

所以知识库的职能是**索引**，不是**副本**。这条前提决定了下面所有标准。

**为什么搜索替代不了索引**：只有当用户语言和代码术语一致时（「合同」→ `contract`），
`search_project_text` 才能一次命中。用户说「付钱的时候没让我签字」，代码里是 `signContract`——
搜「签字」什么也搜不到。术语对不上的那部分，正是知识库的主场。

搜索还有一个替代不了的：**跨位置的关联**。合同在 `orderBusiness/`、协议在 `cashDesk/`，
分别搜「合同」「协议」会落到两个不相干的地方——「它俩是同一条链路的两个分支」这个关联，
只有索引能给。

## 一、三道筛子（顺序执行，任一不过就不入库）

### 1. 这条是「索引」还是「副本」？

| | 例子 | 处理 |
| --- | --- | --- |
| **索引**：用户语言 → 代码位置的映射 | 「没让我签合同」→ `ConfirmOrderPage`（合同）／`XesAppCashierDeskViewController`（协议），且两者分属不同模块 | **入库** |
| **副本**：把代码里的规则用自然语言重写一遍 | 「签约条件是 `needSignContract===1 && onePersonClass===1 && state===0`」——agent 读一眼函数就知道 | **不入库** |

判据：**拿着用户的原话，agent 自己能不能找到对应代码？**

- 能（术语一致、一次搜索命中）→ 索引价值低，除非它能提供搜索给不了的关联；
- 不能（术语对不上、跨模块、需要业务背景）→ **必须入库**。

### 2. C 端用户能不能感知？

**不能 → 不入库。**

排查助手服务的是 C 端——学而思 / 学而思HD / 学家云 / 学家云HD，孩子用的那四个 app。
纯 B 端、后台、运营侧的需求不直接入库。

**按「C 端能否感知」判，不是按「需求归属哪个系统」判。**
反例：合同配置功能做在班课系统（B 端），但它决定 C 端购课页展示什么 → **该入库**。

匹配词表（扫 PRD 用）：

| 产品 | 匹配词 |
| --- | --- |
| 学而思 | 学而思、xesApp |
| 学而思HD | 学而思HD、xesAppPad、pad端 |
| 学家云 | 学家云、xuejiayunapp |
| 学家云HD | 学家云HD |
| 泛指四个 | C端、孩子端、学生端 |

「端」是**业务场景标签，不是文档分类**：一个 PRD 常同时覆盖 C端/B端/小程序端。
出现「B端」字样不构成排除理由，**只有完全不含 C 端相关词的文档才不相关**。

### 3. 模型忘了这条，它会答错吗？

**不会 → 它在占位置。**

## 二、入库后怎么标（按证据分级）

| 情况 | `authority` | `verified_at` | 正文必须写 |
| --- | --- | --- | --- |
| 客户端代码核对通过 | `code` | 填核对日期 | 文件路径 + **符号名** |
| 代码核对不到，但文档近期更新 | `internal-sop` | 留空 | 标注「可能是新需求，代码未实现」 |
| 只有文档描述，无代码/工单佐证 | `internal-sop` | 留空 | 标注「只能作线索」 |

## 三、三条硬规则

### 1. 「搜不到」要区分「漏搜」和「本来就没有」

结论进条目之前必须有旁证，否则只能写「未核对」，**不能写「不存在」**。

正面例子：PRD 把「合同作废 / 补签」列在「合同后端」栏下 → 客户端搜不到是**预期结果**。
标注之后，读者才知道那不是漏搜。

### 2. 锚点是索引的载体：锚符号，不锚行号

行号会烂，符号名不会。锚点的作用是**指路**，不是替代阅读——
写「去读 `shouldMoveContractSignToCashier()`」，而不是把那个函数的逻辑抄进来（那是副本，会过期）。

### 3. 来源 URL 是人工核实入口，不是 agent 的入口

agent 读不到知音楼，**也不要给它接知音楼工具**——一旦 agent 能直接翻 PRD 原文，
免策展 RAG 就从后门回来了。条目里的知音楼链接是给人点开核实用的，写的时候标明这一点。

## 四、拉式，不追全量

不搬整个 PRD 库。排查踩到**没有事实条目的领域**时，才蒸馏该领域的文档；
知识库只收索引结果，原文留在知音楼。
