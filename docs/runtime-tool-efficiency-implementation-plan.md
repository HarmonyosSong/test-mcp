# 工具调用浪费修复实施方案

日期：2026-09-29。状态：**实施建议，未因本文而修改运行时或部署配置**。
依据：[2026-09-28 会话审计](../experiments/runtime_audit/REPORT-2026-09-28-conv-1d1e339323.md)。
代码基线：`39a8882` 加当前未提交工作区；部分补丁已在工作区存在，下面分别标注已见改动与仍需解决的问题。

## 1. 目标与本例基线

目标是在保留证据、追问和因果边界的前提下减少无效往返，而不是仅让计数变小。

本例：错题录入选择 PDF 后返回首页。53 个工具请求，49 个预算内请求，45 次实际执行，
4 次缓存复用，4 次停止后拒绝；27 次模型请求，180.847 秒，累计输入 850,994 token、输出 38,124 token。
最终未成功提交结构化报告。至少 12 个请求属于错误绑定、报告协议修复、复用或停止后的开销。

需要同时保住两个判断：

- 实际读取的选择器实现可支撑“该代码路径未设置对应过滤”的源码事实。
- “本次完成后为什么回首页”仍需运行时观测；不能为了少查就把候选写成已确认根因。

本文的接口名、字段和阈值中，标为“新增/建议”的均是待实现设计，不是已有能力。
不承诺本例一定缩到某个次数；真实模型对照后才报告节省比例。

## 2. 当前工作区已见补丁及边界

| 已见改动 | 已改善什么 | 尚未解决什么 |
|---|---|---|
| `EvidenceLedger.max_entries` 120 → 300 | 延后证据淘汰 | 超过 300 仍会删当前轮证据；恢复时也缺少完整容量校验 |
| 缓存复用附 `evidence_refs` | 模型更容易找回 ID | 账本若已删除记录，返回同一个 ID 仍不能校验 |
| 截断提示增加原始字符数 | 告知有信息丢失 | 返回仍可能是截断 JSON；没有实际末行和续读游标 |
| 搜索无新增路径计无进展 | 可发现部分换词绕圈 | 同文件新行/新分支也会被误计无进展；路径不是信息单位 |
| USER 摘录与输入子串比对 | 避免真实用户描述因随机 ID 被拒绝 | USER 不在账本，正向候选校验仍用 `self.entries[eid]`，存在 KeyError 路径；来源字段仍未由运行时统一生成 |
| `LocatorGuidanceToolset` | 搜索后提示已有代码位置 | 调用已经执行；读过文件头不等于读过锚点；跨条目共现容易关联错位置 |
| 提示词约束与预算预警 | 引导收敛 | 不能代替缓存、证据、分页的协议一致性 |

审计会话发生时的错误文案、容量与当前工作区不同，不能把上述补丁当作已经真实验收。
保留现有改动，在它们基础上补全；不要为对齐旧报告回退别人的修改。

## 4. A：证据生命周期与缓存

### 4.1 最小修复：保护当前轮，不靠增大 FIFO

在 `EvidenceLedger` 新增当前轮 ID 集合、开始/结束轮次方法和显式淘汰原因。
`capture` 成功交给模型的 ID 必须标记为当前轮保护；搜索、读取、真实输入观测都遵守同一约束。

规则：

1. 活跃轮内不淘汰已交付观测。历史记录可按容量淘汰，但不能删除当前保护集。
2. 当前轮另设记录数和 UTF-8 字节数硬上限；达到时停止扩展调查，允许用已有观测收尾。
   建议初始实验值 1,000 条、4 MiB，必须配置化并测试边界，不把它们写成通用最优值。
3. admission 要在返回 `evidence_refs` 前完成；拒绝接纳时返回明确 `observation_capacity_reached`，
   不得返回无法引用的 ID。工具已执行但未接纳应如实计量，不能算成功观测。
4. 取消、失败和正常完成共用 `finally`/终态路径，已交付观测不因报告失败而丢失。
5. `restore` 校验 entries/texts 配对、类型、大小和来源，不能读入任意数量后绕过容量检查。

历史容量与当前轮硬上限是两个概念。当前轮超过历史容量时，不得在 snapshot 时直接删掉
仍在保留的工具消息或已提交报告中引用的记录。

### 4.2 跨轮保留策略必须显式选择

推荐分两步交付：

- **A1 最小版本**：当前轮保护记录随终态保留，历史容量作为软目标；总量仍受上一节硬限控制。
  下一轮淘汰历史前，先识别将保留的工具消息与报告引用，保护其依赖。
  若所有记录都被保护且已到硬限，压缩完整旧轮次为不带“可用观测 ID”承诺的摘要，或停止新增观测。
  已归档报告本身保留其完整证据快照，不重新解释为当前快照事实。
- **A2 后续需要长会话时**：引入会话级可信观测存储，内存 300 条仅作为缓存。
  校验缺项可从存储恢复；只有持久化成功的观测才可发出可跨轮引用的 ID。
  存储需按会话、仓库和 commit 隔离，原子写入、完整性摘要、删除会话后的清理、配额失败行为都须测试。
  未实现这层前不要在文档或错误中承诺“所有历史 ID 永久可用”。

已过期 ID 返回 `evidence_expired` 与可用的原观测位置；从未出现的 ID 返回 `unknown_evidence_id`。
两者不应统一说 was not observed。该契约涉及 ADR 0002 的 120 条 FIFO 约定，实施时新增 ADR 说明替代范围，
不要把原决策记录无痕改成新行为。

### 4.3 缓存不只保存 call index

把 `_successes: signature -> call_index` 升级为缓存记录，至少含：

```text
call_index, snapshot_key, canonical_arguments,
bounded_result, evidence_ids, observation_restore_data, returned_ranges
```

- `snapshot_key` 至少包含 repository_id、resolved_commit；独立本地工作区没有 commit 时用明确的工作区代次，
  不把路径相同当作内容未变。
- 调用签名要填入默认参数后再规范化，避免省略默认 limit 与显式同值被当作两次不同操作。
- 复用前核对依赖 ID。缺失但有可信缓存恢复材料时先恢复，再返回有界引用摘要；不重新扫文件。
- 无可恢复材料时失效该缓存项，允许一次真实重读并说明理由；不能既阻止重读又要求引用失效 ID。
- 重绑成功并确实改变快照时清除缓存、定位状态与进展状态。旧快照证据保留来源，不能支撑当前快照断言。
  同快照幂等绑定无需清空有效缓存。
- 完全相同复用通常不算新进展；恢复了此前不可用的观测则单独记 `evidence_restored`，
  不把一次有效修复立即推入“无进展”停止。

## 5. B：源码读取和搜索返回协议

### 5.1 在真正的读取层限制大小

修改 `mcp_server/src/harmony_repo_mcp/inspector.py` 与 `schemas.py`，同步两套入口：
`tools/file_reader.py`、`tools/code_search.py` 和 `agent/.../toolsets/chat_workspace.py`。
只改独立 MCP 包装会遗漏当前聊天实际使用的 FunctionToolset。

保留 read 的路径与行参数，新增可选字符预算（建议默认 6,000、上限 12,000，实验值）。
`FileContent` 保留原字段并增加明确游标；示例为设计示意：

```json
{
  "path": "module/File.ets",
  "start_line": 120,
  "end_line": 158,
  "requested_end_line": 200,
  "total_lines": 430,
  "content": "120: ...\n...\n158: ...",
  "truncated": true,
  "next_line": 159,
  "has_more_in_file": true,
  "truncation_reason": "character_budget"
}
```

- start/end 表示实际完整返回范围；truncated 表示请求范围未完整返回，不能继续沿用“文件后面还有内容”的旧含义。
- `next_line` 只在本次请求范围仍有缺段时给出；整个请求已读完则 null，即使文件还有后文。
- 行号与格式开销计入预算。不得把第 159 行切一半再声称已读完它。
- 单行大于硬上限时返回结构化 `line_too_long`，说明该行未作为完整观测交付；禁止无进展游标循环。
- 明确空文件、起点超过 EOF、非法范围的行为。不要返回 end_line 小于 start_line 却标成正常页。
- 400 行和文件大小、授权路径限制继续存在；新增字符预算不能绕过它们。

### 5.2 搜索也需要有界结构

新增 `SearchPage`（需要迁移当前 list 消费方），包含 matches、truncated、检索范围和稳定的续查信息。
默认小结果集，例如 10 条；单次总预算包含 `evidence_refs`，不能先塞 50 个引用把真正命中内容挤掉。
遍历顺序需确定；达到 `max_search_files` 或结果数上限必须披露，不得据局部无命中声称全仓不存在。

捕获逻辑显式识别 SearchPage.matches；locator_hint 作为独立元数据，不混入 SearchMatch 列表。
只有实际交付的命中正文进入观测账本。分页游标必须绑定 snapshot/query/scope，不能跨条件复用。

### 5.3 Runtime 不再次截坏已经有界的结果

`trim_messages_state` 识别并完整保留通过 schema 和大小检查的源码页、搜索页与引用元数据。
只有确认工具层已限制大小后才加入保留名单；不能给任意同名工具结果无条件免裁剪。
旧版/不受控返回保留结构化截断说明和可读内容，不能继续任意切 JSON 字符串。
当前轮消息与工具调用/返回的完整配对继续保持；请求前裁剪与落盘使用同一规则。

## 6. C：报告改成引用式输入，保留严格验证

新增 `DiagnosisReportDraft` 与 `EvidenceCitation`，模型只提交引用和解释：

```json
{
  "verdict": "insufficient_evidence",
  "summary": "已观察到选择器实现，返回首页的原因仍缺观测",
  "issue_category": "file-selection",
  "confidence": 0.3,
  "evidence": [
    {"id": "ev-existing-id", "excerpt": "逐字存在于该观测中的摘录", "supports": "该读取展示了选择器配置"}
  ],
  "root_cause_candidates": [],
  "missing_information": ["返回 App 首页还是系统桌面"]
}
```

`id` 必填且不设随机默认值；kind/source/location 由服务端从可信观测组装。
先解析引用、核对精确摘录与快照，再构建原 `DiagnosisReport` 并执行原正向结论约束。
持久化与前端读取仍使用原完整报告结构，减少 API/UI 迁移面。
不要直接给 draft 套 `DiagnosisReport` 的旧 evidence schema，也不要同时暴露两个报告工具让模型选择。

USER 输入由运行时按 message_id 与精确原文范围登记，用有界消息把可引用 ID 交给模型。
不必复制完整工单；来源和位置由服务端填入。历史 USER 引用必须与原消息对应。
若暂时保留当前“提交时验证 USER 子串”兼容路径，也要先构造统一的 resolved evidence map，
候选检查在该 map 上执行并显式拒绝仅 USER 的正向候选；禁止直接索引不含 USER 的 ledger.entries。

错误返回固定错误码、出错 ID、原因和有界可用引用信息：unknown、expired、snapshot_mismatch、
excerpt_mismatch、positive_without_observed_source。不向模型倾倒整份账本。
未通过验证不能设置 holder.report；失败也不能清掉已有观测。

### 收尾预算

将调查工具与报告收尾工具分组。总预算继续是硬限，例如保留其中最后 2 次供报告提交与一次纠错，
并非在 50 次之外无限额外调用。调查无进展停止时关闭调查工具，保留有界报告收尾和自然语言输出。
提交成功或达到两次收尾尝试后关闭报告工具；不要用多次改写报告绕开失败预算。
失败、工具不可用、取消时都保留原调用/返回配对与终态指标。

## 7. D：减少发散而不误拦同文件调查

### 7.1 信息单位从 path 改为观测范围

源码搜索新信息可用 `(snapshot, path, line, excerpt_hash)` 近似；
读取用已实际交付的完整行区间及内容摘要判断。不要只用文件集合。

- 同文件 140 行后新命中 317 行：算新信息。
- 换 query 仍返回完全相同的行与正文：计无新增观测。
- 新 commit 相同文件行号：不是旧快照信息。
- 知识检索按条目 ID 和内容版本识别，不能与源码路径共用同一规则。

这只能判断新观测，不能证明业务上有帮助。不要把新路径/新内容计数命名为“有效诊断进展”。

### 7.2 定位提示要在调用前有用

优先在知识返回中附少量结构化 `suggested_reads`，让模型第一次就能按锚点读。
不要默认多加一个“获取锚点”工具调用。知识锚点仍是线索，必须实际读取后才能生成源码证据。

补全当前 locator_guidance：逐条文档解析，保留 entry_id 和来源边界；
代码路径跨行/同文多文件不明确时不强配符号。按实际返回行区间标记已读，
读 1–50 不能消除 163 行锚点提示。切换快照清空已读状态。
裸符号采用完整边界匹配，不能因 query 含其子串就重定向。

如果仍使用搜索后附提示，必须标明它只影响后续行为，不能声称省掉了已执行的这次搜索。

### 7.3 提问与停止条件

更新 prompts 与定位 Skill：已知文件/行号先局部读；没有新锚点时不靠英文、拼音反复猜名称。
同一未决问题经过两次不同而有依据的定位仍无法收窄时，陈述边界并问可区分分支的问题。
“两次”是策略起点，不是任何两次搜索后都硬停；新错误码、调用方或运行时日志到来可继续。

本例应先区分“PDF 可选”和“完成后回首页”两个子问题；前者可由源码观察，
后者在缺用户观测时优先问返回位置与图片对照，不展开路由、崩溃、H5 导航全部分支。
不得自动将“没搜到”写成已排除。

绑定前在运行时状态中提供已登记仓库的名称/ID和默认分支，不暴露凭据或完整敏感 URL。
仓库多且用户未指定时询问；不得把业务功能名当仓库试错。已有绑定复用原 commit。

## 8. E：指标、兼容与验证

保留旧 calls 口径用于历史对比，新增 schema_version 和以下独立计数：

```text
attempted, accepted, executed, reused, blocked,
report_attempts, report_validation_failures,
evidence_restored, evidence_expired,
source_pages_truncated, no_new_observation_calls
```

accepted 可兼容旧 calls；稳定终态满足 attempted = accepted + blocked。
这里 blocked 包含进入预算前被参数校验、工具可用性或配额检查拒绝的请求，需在统一事件层归集；
不能只统计预算包装器抛出的拒绝。取消时仍在途的请求另记 pending/cancelled，不能硬套终态等式。
accepted 内还包含未执行的重复失败签名拒绝，不能无条件写成 executed + reused。
事件入口计 attempted；预算入口计 accepted；所有分支包括停止后的拒绝都要记录，避免双计。
失败或取消保留已发生的成本；供应商没有 usage 时记未知，不能记零。
result_chars 是字符量而非 token；持续记录模型请求、累计 token、运行时间、报告是否通过及质量标签。

### 必需确定性回归

| 用例 | 断言 |
|---|---|
| 先读关键文件，再加入超过历史容量的搜索观测 | 本轮早期 ID 仍能提交；达到硬容量时明确停止，不静默删引用 |
| 可信缓存依赖从热账本移除后复用 | 恢复观测且无真实重读；无法恢复时允许一次明确重读 |
| 同快照与换 commit 的同参数读取 | 前者复用，后者不复用，旧证据保留旧快照归属 |
| 请求 1–200，字符预算只容纳 1–95 | end_line=95，next_line=96；续读不漏行、不截坏结构 |
| 超长单行、空文件、EOF、范围错误 | 行为明确，没有相同游标死循环或伪造完整页 |
| 搜索到不同文件或同文件不同关键行 | 都可产生新观测；相同内容换参数不算新观测 |
| 只读文件头后仍有后部锚点 | 继续保留后部 suggested_reads |
| USER-only 正向报告 | 明确拒绝，无 KeyError；合法 USER 的不足证据报告可通过 |
| 假 ID、改来源、非精确摘录、旧快照断言 | 持续拒绝，不为降低失败率放松约束 |
| 调查无进展后提交合法报告 | 在保留的收尾额度内通过，不能恢复任意调查工具 |
| 同一批次触发停止还有剩余调用 | 每个有返回，blocked 可计量，实际执行不超过预算 |
| 历史 v1 快照、重启、取消和客户端断开 | 兼容读取、终态落盘、无孤立 tool-call |

优先扩展 `agent/tests/test_runtime_efficiency.py`、`test_tool_failure_budget.py`、
`test_chat_agent.py`、`test_locator_guidance.py`、`mcp_server/tests/test_inspector.py`；
在 `agent/evals/test_diagnosis_regression.py` 增加真实工具链、脚本模型的长轮次夹具。
老测试若直接要求“超过容量必删最早记录”，需改为验证新生命周期，而非直接删掉覆盖。

### 真实对照

先用脱敏的本例和图片失败、缺入口、未知仓库、跨轮引用、另一个产品的 PDF 上传等对照问题。
固定模型/参数、源码 commit、知识文件和工具预算，各问题重复至少三次，记录所有成功与失败。
质量先检查事实正确、未越权确认根因、合理追问、引用可追溯，再看调用与 token 是否下降。
本例正常路径无错误绑定、无重复恢复循环、无伪造证据修复往返，作为确定性目标；
真实总调用次数与节省比例只有跑完后才能填写。

本仓库已有检查命令：

```sh
uv run --project server pytest -q agent/tests agent/evals mcp_server/tests server/tests
make knowledge-validate
uv run --project mcp_server pytest -q mcp_server/tests/test_knowledge_base.py mcp_server/tests/test_query_log.py
make lint
```

`make live-eval` 是已有真实模型入口，但当前固定集不自动包含本例；先增加脱敏评测夹具，
再按现有 evaluation 入口运行。缺模型配置或没执行时应明确标记未验证。

## 9. 交付与回滚

每阶段保留版本化快照和兼容解析；旧已归档报告继续按原 schema 展示，不批量重写历史会话。
缓存键和证据来源增加版本后不能混用旧错误缓存。回滚读取器时同时回滚其 schema 消费方，
不要只回滚 MCP 或只回滚聊天工具。运行进程需要重启才会加载新代码，但本方案编写阶段未执行重启。

最终交付应包含：代码差异、接口样例、上表回归结果、真实对照全部样本及成本、
仍然未定位的分支与已知限制。知识检索效果和运行时工具效率分别归因，不能混报。
