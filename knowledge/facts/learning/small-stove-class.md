# 小灶课（「第 0 课」）

## 事实

**小灶课**是老师给学生开的额外辅导课；1对1 场景下由系统**自动创建**，课程名就叫「**第 0 课**」
——正式课之前先上一次。

**自动创建规则**（v4.1 口径）：

| 项 | 值 |
| --- | --- |
| 触发 | 订单侧传递教师、学员、原班 ID |
| **兜底** | 原班首次课开始时间 − 当前时间 **< 48 小时**时**不创建** |
| 课程名称 | 第 0 课 |
| 课程类型 / 用途 | 自建课 / 小灶课 |
| 授课类型 / 形式 | **在线**（统一走自建课链路）；上课形式 = 在线课堂 / **腾讯会议** / 面授 |
| **课程时间** | 日期 = **首次课日期 − 1 天**；时间 = **首次课时间 + 30 分钟** |
| 特殊标识 | 1v1 小灶课——**不让删，只能改时间** |
| 资源 | **只开班，不走时段占用**（不占教师时段） |

**上课形式有 3 种**：**在线课堂 / 腾讯会议 / 面授**（下游履约要求记录）。
因为小灶课**统一走「授课类型 = 在线」的自建课链路**，会撞上
「**幼儿部 / 小学部的学前班年级不允许开在线课**」这条合规限制（**默认整体不允许**，
只对「**广州 ＋ 活动课**」这类组合做过配置化放开）——小灶课 3.0 专门**放开了**这些年级：
早教 / 托班 / 小班 / 中班 / 大班 / 幼儿组 / 幼小组 / 学前班。
但**创建端会限制「学前只能走上课形式 = 面授」**（上游确认过的风险点），
所以**学前年级的小灶课在线形式仍可能开不出来**。

**前身叫「密令课」**：1对1 的密令课原本用于两个场景——**补课**（原班课次有异常）和
**家长会**（课前 / 课中 / 课后）。培优系统先有自建课，1对1 是在它基础上改造的。
**教师 APP 侧还压着一层审批**：班主任创建自建课后要**上级审批**，通过后才与班课交互
——**班课侧无感知**，连修改和删除能力都被隐藏了。
1对1 侧直到《1对1班课v12.5-自建课支持变动、关闭》才支持**改时间**和**关闭**两个动作。

**它在订单 / 报名侧还叫「0 次课」**——而且**「0 次课」的识别范围就是这五项的组合**：

| 维度 | 值 |
| --- | --- |
| **课程类型** | 自建课 |
| **课程用途** | 小灶课 |
| **授课类型** | 在线 |
| **上课形式** | 腾讯会议 |
| **创建类型** | **系统**（所以**不能删**） |

**为什么这条重要**：**0 次课不占用时段，因此没有时段 ID**——
**报名处理教师请假 / 学员请假时要把 0 次课整体过滤掉**，否则会因为查不到时段 ID 而**请假报错**。
所以「**老师请假报错**」的一个可能原因就是这类课没被正确过滤。

**整班换师**时：原教师有未开的小灶课 → **关班**；新教师需要 → **开新小灶课**。
教师也能在**教师 APP** 侧自主创建（v5 起）。

**C 端侧的关键差异**：客户端**不叫「小灶课」，显示为「自建课」**。

**卡片什么时候出现、能不能点进去，按「服务与上课形式」分**——这是最容易误判成 bug 的地方：

| 上课形式 | 卡片展示 | 点击跳转 |
| --- | --- | --- |
| **在线** | 上课当日 **0 时**展示，**下课后卡片消失**（阅后即焚）⚠️**与下方"1对1 不阅后即焚"存在歧义，见说明** | ✅ 跳转课堂 |
| **腾讯会议** | **不展示** | ❌ 弹 toast「**请按照短信通知的内容操作上课哦~**」 |
| **面授** | **不展示** | ❌ 弹 toast「**请前往教学点上课哦~**」 |

所以「**小灶课卡片没出现 / 点了没反应**」很可能是**上课形式是面授或腾讯会议**，
**不是课没排上**。

**⚠️ 关于「阅后即焚」的一处歧义**：需求原文分两处写——
一处是「自建课_小灶课（**在线**）：上课当日 0 时展示，**下课后卡片消失**」；
另一处是「**1对1** 的自建课卡片**无阅后即焚**；**非 1对1** 的（含小灶课）**阅后即焚**」。
**自动创建的小灶课属于 1对1**——按后者应"不焚"、按前者应"焚"，**原文没有对这两处做交叉说明**。
**遇到"小灶课卡片还在 / 不见了"请以实际版本为准**，别用本表强行判定。

**自建课卡片的通用规则**：

- 上课日期**提前 7 天**开始展示；
- **1对1** 的自建课卡片**不阅后即焚**；**非 1对1** 的（含小灶课）**下课即消失**；
- 「去学习」按钮：1对1 是**上课当日 0 点展示、下课 +30 分钟隐藏**；
  非 1对1 是**当日 0 点展示、下课后卡片直接消失**；
- **合规细节**：**课程结束时间晚于 21:00 时，卡片上的上课时间显示「时间待定」**
  （客户端里能搜到「时间待定」这个实现）。

## 判据

用户问「课表里这个『第 0 课』是什么 / 为什么多了节课 / 腾讯会议怎么上课」时：

1. 那是**小灶课**——系统在正式课前自动排的，上课的就是原班老师；
2. **时间规律**：通常在首次课的**前一天**、首次课时间 **+30 分钟**；
3. 家长会**提前 2 小时收到提醒**；
4. 它**不占老师时段**，且**不能删、只能改时间**；
5. 「怎么没开第 0 课」→ 可能**距首次课不足 48 小时**，系统按规则不创建。

## 例外

- **「首次课 48 小时」不是小灶课独有的**：**全国班的 1对1 在线主讲**排课也卡同一个 48h——
  **正常报课 / 调课（不换师）/ 整班变动-换师** 要求首次课距当前 ≥ 48 小时；
  而 **调课（换师且指定）/ 加课（不换师）/ 整班变动-不换师** 则**不受限**。
  不满足时：**自动返单会排除全国班 1对1 主讲**，**指定排单直接报失败**。
  所以"48h"要在**两个场景里分别对**（小灶课是否创建 / 排课是否放行）；
- 规则以 v4.1 / v5 为准——更早的口径是**提前 2 天 + 24 小时兜底**，已改；
- 「小灶覆盖率」是**教师口碑值**的一项指标（见 `teacher-rating-system`），两处指同一件事；
- 客户端搜「小灶课」**零命中**——C 端叫「自建课」，按"小灶课"搜客户端搜不到。
