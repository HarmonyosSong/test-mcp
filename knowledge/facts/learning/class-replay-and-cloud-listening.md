# 课程回放与云听课的展示规则

## 事实

「教室实况 / 云听课」和「课程回放」的规则要**分两步看**：先判断这门课有没有这个能力，
再看时间窗口。**两步都随课程类型变化**，这是最容易踩的坑。

### 一、这门课有没有

| 课程 | 教室实况 / 云听课 | 课程回放 |
| --- | --- | --- |
| **1对1 + 面授** | ❌ **整体屏蔽**（合规风险，2025-11 起对全部 APP 屏蔽 icon / 标题 / 副标题 / 进教室按钮） | —— |
| **面授 + 大小屏** | ✓（**新面授**；学情分析同条件） | ✓ |
| **面授 / 双师-普通 / 托管** | ✓ ——条件是**业务归属 = 培优 / 素养 / 大学生**，时段规则见下 | ✓（托管**额外**要求课程类型 = 书机结合） |

**⚠️ 先分清四个入口——它们不是一回事**（这是本节最容易混的地方）：

| 名称 | 谁在什么条件下有 |
| --- | --- |
| **学情分析** | **新面授**（授课类型 = 面授、课中交互模式 = 大小屏）；**首课开课时间之后**展示，**无隐藏逻辑** |
| **家长旁听** | **业务归属 = 1对1** 且 **课程类型 = 1人班**——授课类型 / 课中交互模式**都无限制**；**常驻展示**；<br>上课中 icon 是动态效果（是否上课中**调课堂接口判断**） |
| **云听课**（= 教室实况的**新版**） | 面授 ＋ 大小屏；**课前 30 分钟**展示「进教室 / 云听课」btn，**展示后无隐藏**；<br>⚠️ **点击后跳到哪**：需求文档写「跳**家长空间 H5**」，但**客户端那个页面是个内嵌 H5 容器**<br>（`XesClassLearn/src/main/ets/page/ClassLearnYunTingKePage.ets`），**默认加载 `xesConfig.taskAnswerUrl`**、<br>**拿到视频地址后改用视频 URL**——<br>**都不是"家长空间"这个站点名**（见 [[cloudlearn-h5-surfaces]]）。排查时**以实际加载的 URL 为准** |
| **教室实况**（**旧版**） | **仅在课中**展示「进教室」btn；点击跳**教室监控 H5** |

**⚠️ 云听课不是"另一个功能"，而是「教室实况」的功能迭代**——**同一个入口按钮，
按 APP 版本走不同逻辑**：

| APP 版本 | 行为 |
| **低于 `V7.79.0`** | 沿用旧逻辑：**课中**展示「进教室」，跳**教室监控** |
| **不低于 `V7.79.0`** | 新逻辑：**课前 30 分钟**展示「云听课」，跳**家长空间 H5**（Pad 端无版本限制） |

**⚠️ 杭州 / 贵阳的 3~6 年级是特例**：这两个城市的 **3~6 年级**
（三年级 / 四年级 / 五年级 / 六年级 / 小高，即**年级 ID `3`、`4`、`5`、`6`、`25`**）
**屏蔽「云听课」与「学情分析」**，改走**教室监控**逻辑；
判断条件是**学员注册城市 = 杭州 / 贵阳**且**课程属性年级**在其中。

**学情分析的入口排序**：`0` 添加老师微信 → `1` 关注公众号 → `2` 学情分析。

**「家长旁听」在课次上是屏蔽的**——学习二级页能看到，**课次上不展示**。

**⚠️ 1对1 面授这一格有两个口径，**必须先对齐再下结论**：屏蔽教室实况的依据是 2025-11-13 的
《【1118】1对1面授课屏蔽教室实况功能》（合规风险）；但**12 天后的**
《251218 | 班课-高中1对1云听课默认开启》却要求——**高中**（高一 / 高二 / 高三）**1对1 1人班面授**班
在开班时把「**云听课**」字段**自动置为开启**（范围：业务线=1对1 & 1人班 & 高中 & 非自建课 & 面授；
场景：续报、新签、换商品、加课触发的新开班）。
一个在**客户端展示层**、一个在**班课字段层**，**无法直接判断谁覆盖谁**——
遇到高中 1对1 云听课问题，**按当前版本实测**再下结论。

**托管班的云听课字段是「默认关闭」的**：素养托管业务负责人确认暂不需要云听课，因此**新增与导入的托管课程
默认关闭云听课**，批量修改也不支持打开。

**⚠️ 但不要拿这个开关去解释 C 端看不到**——2024-09 的需求里明确写了：
「班课系统的【**是否支持云听课**】的配置规则，**在下游系统（含 APP-学习二级页）是不解析和做逻辑判断的**」。
也就是说 **C 端展不展示，看的是授课类型 / 业务归属 / 时间窗口，而不是班课那个开关的状态**。
（这条结论出自 2024-09，**后续版本是否开始解析需实测**；但至少不能默认"开关关了客户端就不显示"。）
（**前因**：2024-09《班课-云听课能力调整》先把云听课扩到**托管 / 面授 / 双师**、
新增时**默认是、可修改**——托管"默认关闭"是 2024-12 才定的口径。）

**两个术语的出处**：`大小屏`、`书机结合` 来自班课的「**课中交互模式**」字段
（枚举：`0-普通`（默认）/ `1-智能伴学` / `2-书机结合` / `3-大小屏`）——托管 AI 可选 1、2，
面授普通可选 0、3，**选定后不可更改**（换产品也不支持更换）。

**托管班的两种「上课模式」**（这是"有没有回放"的关键）——⚠️ **先说清字段名**：
托管支持「**书机结合**」与「**智能伴学**」，**这两个值属于「课中交互模式」字段**
（就是上一段那个字段），对应 `livetype` **23** 与 **22**；
但**班课的需求文档习惯把它口语称作「上课模式」**（如《240130 托管班级支持2种上课模式》），
而**课程/班级维度另有一个真的叫「上课模式」的字段**（小班课 / 组合小班课 / 新通用课 等）。
**两个"上课模式"不是一回事**，辨析见 [[class-mode-vs-interaction-mode]]。

业务线支持范围**随时间变过**：

| 业务线 | 书机结合 | 智能伴学 |
| --- | --- | --- |
| 彼芯 | ✅ | ✅ |
| **培优** | ✅（**2024-10 起放开**，此前不支持） | ✅ |
| 大学生 / 素养 | ✅ | —— |

培优放开「书机结合」是为了承接「面授-普通」秋季班 →「托管-书机结合」寒假班的续报。

**彼芯内部还要按「商品 / 班级」分**：**彼芯商品**在课堂系统只走「**书机结合**」——
配成智能伴学的产品会被直接过滤，提示「仅支持课中交互模式为"书机结合"的产品」；
而**彼芯班级**（双师 AI）走「**智能伴学**」。所以判断彼芯某门托管课有没有回放，
还要看它是**商品开的班**还是**班级**。

所以要判断「这个托管班为什么没有回放」，**先看它的课中交互模式——只有「书机结合」的托管课才有回放**
（口语里会被说成"上课模式"，指的是同一个字段）。

### 二、时间窗口

**① 面授 + 大小屏**：

| 功能 | 时机 |
| --- | --- |
| **云听课** | 上课**前 30 分钟**起；**无回放资源时下课后继续展示**；长久可用 |
| **课程回放** | 下课**后 30 分钟**起，到「回放过期时间」为止 |

**② 面授 / 双师-普通 / 托管**：

**展示条件**（都要满足）：**授课类型 ∈ {面授、双师-普通、托管}** 且
**业务归属 ∈ {培优、素养、大学生}**——**这套规则对这三种授课类型通用，不只是托管**。

| 功能 | 时机 |
| --- | --- |
| **教室实况** | 上课 **-10min 以前**：展示但**置灰**；-10min ~ 下课 +10min：**高亮可点**；下课 **+10min 后隐藏** |
| **回放视频** | 下课 **+30min 后**开始展示，视频过期后隐藏入口 |

托管班另有一条展示差异：**教室地址前会拼接固定文案「（请前往教学点）」**。

### 三、回放入口的三种状态（不是简单的"有 / 无"）

| 状态 | 含义 |
| --- | --- |
| **无回放** | 从在线课堂服务查不到本节课上传的回放视频 |
| **生成中** | 视频已上传、但服务端尚未处理完成 |
| **看回放** | 查到了视频，且已到展示时间 |

入口隐藏时间取**班课系统里课程的回放有效期**。

**⚠️「生成中」这个状态是有争议的**：`ics3.0`（面授 + 大小屏）的需求里，
这一行被**划掉并标注「不存在此状态」**，只剩 **无回放 / 看回放** 两种；
而托管侧的需求（≥ v7.87.0 那份）是**三种状态**。
所以**状态表按业务线分**：面授 + 大小屏**只看两种**，别按三种找。

**又一套口径（`ics3.0` 面授 + 大小屏，2025-05）**——与上面不完全一致，**按场景分别看**：

| 栏目 | 规则 |
| --- | --- |
| **云听课栏目** | icon ＋ 文案「**教室实况**」（⚠️ 此处文案**不叫"云听课"**）；时间取**上课 ~ 下课**；<br>**课前 30min 开始展示**；**下课 +30min 且"有回放视频可展示"时才隐藏**（**没有回放就继续展示**）；<br>**只有高亮可点击一种状态**（无置灰态）；跳**家长空间详情页** |
| **回放视频栏目** | 标题「**课程回放**」；**下课 +30min 开始展示**；**视频过期后隐藏**（取班课的**回放课程有效期**）；<br>按钮只有 **无回放 / 看回放**；跳**客户端原生播放器**（**视频无交互**）；**学习环节隐藏** |

**展示前提**（这条是 `ics3.0` 特有的）：**授课类型 = 面授**、**课中交互模式 = 大小屏**、
**且课件里配了回放视频**——是否配置要**调课堂接口查询**，判据是**超过 30 分钟的视频**。

**回放入口还会带「观看进度」**：学习二级页的回放按钮文案是「**观看进度：xx%**」
（数值**取整、无小数**）；**进度为 0 或为空时文案维持原样**（「看回放」/「已完成」）。
进度数据由**课堂团队**提供接口。
**注意**：这条需求的范围写的是 **iOS & Android，没有列鸿蒙**——鸿蒙端有没有这个文案要实测。

**无回放视频资源时**，规则是**隐藏回放入口、保留云听课**——而不是两个入口都空
（这是历史上专门调整过的：不让"没有回放"导致整块消失）。

二者在学习二级页是**互斥展示**的。

## 判据

用户说「看不到回放 / 云听课」时，**按两步排查**：

**第一步：这门课该不该有？**

1. **是 1对1 面授吗** —— 教室实况**整体屏蔽**，看不到是设计如此（合规要求）；
2. **是托管班但没回放吗** —— 检查「课程类型」是否 **书机结合**，不是所有托管班都有回放。

**第二步：时间对不对？**

3. **是不是刚下课不到 30 分钟** —— 各口径下回放都要下课后 30 分钟才出现；
4. **是不是已经过了回放有效期** —— 入口会隐藏；
5. **「教室实况点不动」** —— 托管班在上课前 10 分钟之前是**置灰**（展示但不可点）；
   下课 +10min 后直接隐藏；
6. **回放显示「生成中」** —— 视频上传了但服务端还没处理完，等一会儿，不是故障。

## 例外

- 规则**只覆盖「面授 + 大小屏」**的课程，其他课程类型另算；
- 「回放」与「云听课」互斥展示，历史上调整过多次（ics3.0 回放、素养托管云听课等），
  以**当前版本**为准。
