# 购课前的「开课须知」确认

## 事实

购课流程新增开课须知确认环节（需求 2026-09-21 定稿，1 期）：

- **触发场景**：APP 在落地收银台**前**弹出；小程序在落地订单确认页**前**弹出；扫码付在落地订单详情**前**弹出；
  待付款按下单渠道判断（盘古、教务下单同样要弹）；
- **流程**：弹窗 → 上滑读完全文 → 一键抄入「本人已阅读并知悉「XX须知」」→ 点确认才能继续；
  未读完、未抄写时确认按钮不可点；
- **生效范围**：按**分校 + 业务线**灰度（另覆盖学部，1对1 不开）；**没配灰度就不走这个流程**；
- **多份须知**：一次下单包含多份只展示一份——年部不一致优先高年级，年部一致优先素养，再否则取第一个班级；
  合同按优先级顺序返回须知 ID，**端上自己做展示逻辑**；
- **留档**：记「报名ID + 开课须知名称 + 开课须知ID + 签约日期」，其中 ID 记的是**签约时绑定**的那份，
  不是当前业务线+年部关联的那份。

## 判据

用户说「付款前让我抄一段话 / 弹窗读不完 / 没看到须知」时：

1. 先看是否命中灰度范围（分校 + 业务线）——**不在范围内本来就不弹**；
2. 抄写不一致时提示「抄写内容有误，可点一键输入快速更正」是设计好的交互，不是故障；
3. **当前客户端代码里没有任何开课须知实现**（见下），所以"该弹没弹"在现状下不是客户端 bug。

## 例外

- 需求本身仍有多个待确认项（是否强制签约才能付款、B 端下单是否补签、须知颗粒度），**实现形态可能变**；
- 现金支付走线下签约，线上流程不做处理。
