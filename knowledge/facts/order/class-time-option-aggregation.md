# 上课时间选项是怎么来的

## 事实

选课页的「上课时间」**不是一个具体值，而是把该班各课次的上课时间「去重聚合」后的结果**。

**歧义从哪来**：如果某个课次的时间与其它课次不同（例如每周五上课，但其中一次因调休调到了周日），
聚合后就会展示成 **[周五、周日]**——用户选"周日"时**并不知道自己选的是什么**
（周日只上一次，并不是每周日都上）。

**班课侧的解法**：在**课次维度**新增「**是否外显**」字段（默认「是」；允许变动，但**不能全是「否」**）：

- 选「否」时，**上课时间总览与 C 端的时间选项都不聚合该课次的时间**；
- 也就是业务可以剔除个别课次，让选项回归干净。

**为什么从彼芯起**：这项能力 **2024-04 最初只给彼芯小程序做**（为了让详情页的时间选项聚合干净
——彼芯**购前不展示大纲、时间又必选**，最容易踩"选错时间"）。

**它的沿革要留意——这项配置一度失效过**（排查老班次时会遇到）：

1. **2024-09**：非彼芯线陆续开托管班，但**培优 APP 与小程序都不展示课次信息**，
   这项配置化对它们**无意义**；
2. **2025-01**：彼芯小程序只剩彼芯业务线且**四年级及以下**还在用；
3. **随后**：该配置在**托管模式调整后消失**，导致**班级变动无法通过**（业务实际反馈的问题）；
4. **2025-06 补回**：新增/导入时**仅校验彼芯，其它业务线不校验**——所以**非彼芯的班可能整班都是"否"**，
   后台注释原文即「售卖端不包含彼芯小程序时，可忽略该配置」。

## 判据

用户说「上课时间选项不对 / 为什么只有周五周日 / 我选的时间上不了课」时：

1. **选项是聚合值**——不代表"每周都这个时间"，实际安排要看**大纲 / 课表**里每个课次；
2. **歧义来自个别课次的时间差异**（调休、老师临时变化），不是数据错误；
3. **购前不展示大纲**的场景（如彼芯）最容易踩这个坑，应提示用户去看课表。

## 例外

- 「是否外显」是**班课侧配置**（老师在后台设），C 端只被动接收聚合结果；
- **导入时仅校验彼芯**——非彼芯业务线的课次时间字段不规范属正常；
- 「是否外显」这个字段**跟着托管模式的改造消失过一段时间**，
  所以**老班次可能根本没有这个字段**（那时的班级变动会卡住）；
- **上课时段本身有「最晚开班时间」限制**：原口径是**面授 20:30、在线和双师 21:00**，
  2024-01 起**统一延至 23:00**（各分校可按当地政策灵活使用）——所以 21 点以后开课的班是**放开的**，
  不是配置错了；另外课堂曾**读班课的开班时间配置、超时就断流**，后来放开允许拖堂，
  「课上到一半断了」要先分清是哪套口径。
