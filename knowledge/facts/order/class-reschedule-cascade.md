# 调课引起的课次顺延与短信口径

## 事实

**调一次课，影响的不是那一次**：把第 3 次课从「4月3号」改到「4月9号」之后，
**第 3 至第 8 课次会整体变化**——第 3 次课的时间变成**原第 4 次课的时间**，依次顺延。
所以用户看到「后面几次课的时间都变了」是**连锁结果，不是数据错乱**。

**调课短信刻意不报「是第几次课」**——业务给的口径是：

> **不需要用户感知是第几次课变化，只需要告诉「原时间 → 新时间」的变化**，
> 和业务操作保持一致。

短信模板「1人班调课成功-家长 2.0」：

```
家长您好，{studentName}同学《{className}》的原「{oldClassTime}」课次已调课成功。
调整后的上课时间：{newClassTime}，上课老师：{teacherName}，上课地点：{classArea}，
请您知悉并提醒孩子准时上课。
```

| 项 | 值 |
| --- | --- |
| 触发时机 | **1对1 - 盘古调班课的调课接口成功后** |
| 发送对象 | **学员**（另有一份给**课次新主讲**，文案略不同） |
| `classArea` | 该讲次变动后的教学点；**为空时显示「在线授课」** |

**⚠️ 这套短信存在两个版本，别拿错模板对文案**：

| 版本 | 文案特征 | 出处 |
| --- | --- | --- |
| **不带次数**（2024-04 改版） | 「原「{oldClassTime}」课次已调课成功。调整后的上课时间：{newClassTime}」 | 《240521 | 1对1班课v12.2-调课短信内容修改》 |
| **带次数** | 「第 {classNo} 次课程已调课成功。调整后的上课老师：{teacherName}…」 | 《1对1短信-班课触发》汇总表（2025-08 更新） |

两份材料口径**不一致**（汇总表可能没跟着改版同步），**以线上实际收到的短信为准**。

**「课程变动」是另一个短信场景**（别和调课混）：**1对1 - 1人班**的**课程变动操作完成后**，
也会给家长发一条短信，带上**变动后的班级信息**（上课老师 / 地点 / 时间）。两个参数值得注意：

- **上课时间取「剩余课次的首次课时间」**；
- **上课地点如果是虚拟教学点，展示「虚拟教室（直播）」**。

另外 **1对1 换商品（多退 / 等价 / 少补）在 2026-01 之前是没有短信的**，
本期才补上；同批还补了「**修改考勤转特殊课次**」的短信。

**为什么改课次时间必须走「盘古 / 小驴」的官方路径**——根因是**课件绑在直播讲 id 上**：

课次信息变化时，原实现是「调课堂接口生成**新的直播讲 id** → 替换原课次上的 id」，
而**课件绑在直播讲 id 上，一换 id 课件就没了**，直接影响主讲备课（一次次调整效率极低）。
所以改成**课次时间 / 名称变化时不更新直播讲 id**——
**但只有官方路径（盘古 / 小驴的调课、整班变动、整班挂起）能保证**；
**在一站式班课平台自己改课次时间，无法保证课件不丢**。

## 判据

用户说「课表怎么全变了 / 短信时间不对」时：

1. **先问是不是调过一次课**——调课会让**后续课次整体顺延**，"后面几次课都变了"是预期内的；
2. **「短信时间和我记的那次课对不上」**——短信按「原时间 → 新时间」表述、**不标第几次课**，
   用户容易和自己记的"第几次课"错位，**不是发错了**；
3. **以学习页 / 课表为准**，短信只是通知；课表本身才是资源实际占用的结果。

## 例外

- 口径来自 2024-04 的 1对1 短信需求，**后续模板可能已迭代**；
- 「调课」入口在**我的 - 学习服务**里（见 [[my-page-entries]]）；
- **先学后付前 3 讲次屏蔽调课**（见 [[learn-first-pay-later]]）——遇到"调不了课"先看这条；
- **国素（国际）支持跨年级调课**（2026-08）：因为国际不同年级不同班型**内容可能完全相同**
  （如 3年级a班 / 2年级a+班 / 1年级s班），分班只是为了**同龄分层**；
  而**国素学员少、同年级可调班级更少**，所以放开跨年级调课——
  范围 **国际业务线、学科=国际、年级=学前~小六**，
  条件**同分校 / 同学科 / 同学季 / 同进度**，**年级上下浮动仅 1 个年级**，
  且**只在盘古端开放**（直接放开风险太高），**只放开调课、不放开转班**；
- **退费会让未履约的调课记录一并取消**：用户退费时如果还有**未履约的调课记录**，
  这些记录**会被取消**；用户再次报名同一个班时，**往往以为调课还保留着**，
  发现对不上就投诉。所以退费环节会在**盘古端**给顾问做**前置提醒**
  （2026-11 的需求，**C 端还没开放**）——C 端遇到这类"我的调课不见了"，
  答案通常是**中间退过一次费**。
