# 3+X（短期班 ＋ 长期班的组合）

## 事实

**「3+X」＝ 短期班（3 节）＋ 长期班（X 节）的组合售卖**——学员先上 3 节短期课，再进长期班。
历史需求文档里管它叫「**1对1 支持短+长优惠**」——**两个名字指的是同一件事**。

**它让长期班多出一个特殊形态**：因为是接着短期班上，**这个长期班本身少了 3 节课**——
所以它的**首次课报课日期要从「第 4 周」开始选**，不是第 1 周。文档里的原话是
「长期班本身课次少了 3 节，理论上首次课要从第 4 周开始选」。

**首次课报课时间的算法**（`M周N次` 类型）：

> 首次课报课结束时间 = 按**短期班剩余课次顺延** X 天，
> 其中 **`X = 短期班剩余课次 × 7 × M`**，**这个 X 由端上算好传过来**。

**参与资格**：**只有「学科新生」可以参与**。而这个**新生的口径在 2026-03 调整过**：

| 口径 | 定义 |
| --- | --- |
| **旧** | 学员编号 ＋ 学科**有课表** |
| **新** | 学员编号 ＋ 学科**有考勤**（已上课 / 过课时） |

**为什么要改**：3+X 开在**春季**，而学员可能**先买寒季、再买春季**——
按旧口径，买过寒季就算"有课表"，反而**不能参与 3+X**，只能先退掉寒季的课再买，操作很麻烦。

## 判据

1. **「这个长期班怎么开课时间偏后 / 少了几节课」** → 可能是 **3+X**——
   长期班**接在 3 节短期班之后**，首次课从第 4 周起，课次总数也少 3 节；
2. **「为什么参加不了 3+X」** → 只有**学科新生**能参与，且口径是「**有考勤**」（不是"有课表"）；
3. **别在客户端找「3+X」** ——「3+X」「短+长」在客户端**零命中**，
   它是**售卖侧 / 盘古**的概念。

## 例外

- 「3+X」为什么是 3 节、优惠怎么算，**以当前版本为准**（文档只说"短+长优惠"）；
- **`指定日期` 类型的 3+X 处理当时被划掉（未做）**——只有 `M周N次` 类型有明确算法；
- 同批需求里还有「**1对1 - 在线关闭 0 次课**」「**0 次课开通时间调整**」「**0 次课校历查询规则优化**」
  （0 次课是什么见 [[small-stove-class]]）。
