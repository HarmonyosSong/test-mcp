# 班课的两个「模式」字段（极易混）

## 事实

班课侧有**两个不同的字段**都叫「模式」，**维度不同、枚举不同**——
而且**只差一个字的两个"伴学"分属这两个字段**：

| 字段 | 挂在哪 | 枚举值 |
| --- | --- | --- |
| **上课模式** | **课程 / 班级** | 小班课、组合小班课、新通用课、新小组课、**智慧伴学** |
| **课中交互模式** | **产品** | `0-普通`、`1-智能伴学`、`2-书机结合`、`3-大小屏` |

> **⚠️「智慧伴学」≠「智能伴学」**：前者是**上课模式**的一个值（彼芯在线课堂），
> 后者是**课中交互模式**的值 `1`。两者只差一个字，**不是同一个字段**——
> 学习模块的兼容需求里**原文就是这么写的**：
> 「支持选择上课模式（**智慧伴学，非已有的智能伴学**）」，**一字之差是刻意的**。

**上课模式受「课程限额」约束**（2026-06 口径）：

| 课程限额 | 可选上课模式 |
| --- | --- |
| (0, 35] → 小班 | 小班课、智慧伴学、组合小班课、新通用课、新小组课 |
| [35, 1000000] → 大班 | 组合小班课、新通用课、新小组课 |

- **智慧伴学只在小班可用**，且**业务线仅限彼芯**；
- **不支持接流**（线上组合小班专门支持过接流，智慧伴学不支持）、**不支持切换上课模式**；选修讲支持。

**学习模块不区分上课模式**：彼芯 - 在线的课，**无论上课模式是「智慧伴学」还是普通**，
学习首页（新 / 旧）、日历页、已完结列表、学习二级页**全部复用同一套展示规则**——
所以**「学习页显示不对」不要往上课模式上归因**。

**组合小班的构成约束**：班级限额总和 **≤2000**、单班限额 **≤100**、班级数量 **≤50**。

**课中交互模式**才是决定「**有没有回放**」的那个字段，详见 [[class-replay-and-cloud-listening]]。
各业务线 / 类目的可选值与默认值：

| 类目 | 可选 / 默认 |
| --- | --- |
| **托管AI** | 可选 `1`（智能伴学）、`2`（书机结合） |
| **面授普通** | 可选 `0`（普通）、`3`（大小屏） |
| **双师AI** | **彼芯业务线默认 `1`**；其它业务线默认 `0` |
| 其它 | 默认 `0` |

**「可选 1、2」与「1:1 映射」看着矛盾，其实是两层**（原文容易读岔，这里拆开说）：

- **产品层**：托管AI 的**产品可以配 `1` 或 `2`**——是**二选一**，不是"两个都用"；
- **课程层**：**课程类型与该产品选定的模式做 1:1 映射**——即课程跟着产品走，
  所以「**彼芯班级（双师AI）走智能伴学（`1`）**」是这条映射的产物；
- **「不可更改」**指当时不能换模式——**这条有下文**，见下。

原文一句话同时讲了三件事（可选范围 / 映射关系 / 可否更改），所以**不要拆开单引半句**。

**「选定后不可更改」这句话是有时效的**：2024-09 的口径确实是**选定后不可更改**（换产品也不支持更换）；
但 **2025-06 起面授支持**通过「**课中交互模式变动导入-面授**」修改——
若当前课程的产品条件下没有目标课中交互模式，系统会**自动创建新产品 id**。
所以"这个课的模式能不能改"要**先看是什么时候的口径**。

## 判据

听到这些词时，**先分清是哪个维度**：

1. **「智能伴学 / 书机结合 / 大小屏」** → **课中交互模式**（产品字段）——影响回放与课堂形态；
2. **「智慧伴学 / 组合小班 / 新通用课 / 新小组课 / 小班课」** → **上课模式**（课程 / 班级字段）——受课程限额约束；
3. **两个"伴学"不要互相当成错别字**——先确认说话人在说哪个维度；
4. **问回放问题时要落到「课中交互模式」**，问「上课模式」是问错了字段。

## 例外

- 这两个字段的**中文值在客户端全部零命中**（"上课模式 / 智慧伴学 / 智能伴学 / 组合小班 /
  新通用课 / 书机结合 / 大小屏"），都是**纯后台概念**——客户端只消费结果；
- 上课模式与课程限额的对应**改过口径**：2025-07 的写法是「36~2000 有大班且带组合小班、
  >2000 无组合小班」，2026-06 改成上表——**以较新的为准**；
- 「智慧伴学」是 2026-06 为**彼芯在线课堂**新增的，是否放开到其他业务线以当前版本为准。
