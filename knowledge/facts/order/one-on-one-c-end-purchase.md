# 1对1 短期班的 C 端购买

## 事实

1对1 短期班支持家长在 APP 自助购买（0226 版本先支持单科，0324 版本支持多班一起下单），
链路与班课拉齐：**选择班级 → 报名 → 加入购课单 → 提交订单 → 支付**。

代码位置（鸿蒙侧）：

| 环节 | 模块 |
| --- | --- |
| 购课单 | `XesOrder/src/main/ets/components/shoppingCart/`（`BuyClassListPager`、`CartUniteinfoView`、`model/CartPrepareOrder`、`net/BuyClassListApi`） |
| 下单 / 订单确认页 | `XesOrder/src/main/ets/components/orderBusiness/ConfirmOrderPage.ets` |
| 「1人班」标记 | 模型字段 **`onePersonClass`**（见 `OrderModel` / `ConfirmOrderPage`） |

关键规则：

- **预课表不锁时段**：加入购课单只做展示，能否占用以**下单**为准；
- **加购后课程资源失效 → 2026-07 起改为「展示 ＋ 置灰」**：购课单**会展示失效的 1对1 预课表**，
  按钮**置灰**，统一文案「**该课程已失效，请重新选择**」，并且**支持滑动删除**。
  （**此前是直接隐藏**——结果是冲突资源家长**没法自己取消**，还会**影响 B 端 3+X 购买资格**）；
- **一次最多选 20 个** 1人班商品一起下单；
- 支持 **1人班 + 8人班合并下单**；
- **跨业务线合并下单：从「不支持」变成了支持**——**2026-08 起**在**国际、素养**的基础上，
  放开了「**高中班课 ＋ 1对1**」的合并勾选与合并支付
  （业务背景是「数学班课上得不错，想再买个物理 1对1」这类**组合购买**需求）：

  - **只有购课单与订单支持合并**——**报名子系统的「调转」仍不支持跨业务线**；
  - **能不能组合由订单侧配置**，不满足时提示「**您选择的班级不允许合并下单，请重新选择**」；
  - **订单超时取短**：`下单时间 + min(1对1订单有效期, 班课订单有效期)`；
  - **订单的业务归属会变成「混合」**——业务归属**下沉到订单明细**
    （`tb_goods_detail` 增加 `business_belong` 字段）；
  - **端上展示原则**：订单里**只要含该业务线的班级，就展示完整订单信息**；
  - **合同各走各的**：哪个班需要签合同就走哪个业务线的合同流程——
    **1对1 商品本身也是要签的**（见 [[order-contract-agreement-sources]]），
    只是签约节点被**后置到支付环节**；不要以为"只有班课要签"；
  - **1对1 单独用一个商户编号**——因为**单笔金额大、容易触发风控，会影响班课正常收款**；
    合并支付的短期班单笔金额小，可以按业务实际情况**直接用班课的商编**；
- **长期班和短期班不能一起下单**（**指 1对1 商品之间**；1对1 的长期班当时还不支持 C 端下单）。
  注意这**不是**说"班课长期班不能和 1对1 同单"——**另一个层面的跨业务线合并在 2026-08 已放开**；
- **资源流转**：查看预课表和**报名**都不变；**下单（生成订单号）时才由服务端锁定**教师与教室时段；
  **下单 10 分钟后仍无订单结果，资源自主释放**；缴费后转为占用并自动开班；
- **课次时间计算**：`M周N次` 只支持 **N=1**，其它取值**不展示报名入口**；
  无规律商品首课范围**最多 7 天**，且只能买总课次、不支持自选课次数；
- **商品详情页 CTA**：长期班是「立即预约」→ 跳营业厅小程序顾问二维码页；非长期班才是「立即报名」。
  **游客看不到「立即报名」**（接口需要学员 id），登录后才出现；
- **0 元只对「诊断类」开放**：1v1 商品的**诊断类**课次单价可 **≥ 0**（用来开 0 元诊断课做转化），
  **其它产品类型必须 ≥ 1**——是财务担心 0 元泛滥而做的限制；0 元商品的学员走**无感知流程**。
  0 元在客户端是**领券报名 + 自动报名**，见 [[zero-price-purchase]]；
- **售卖灰度**：业务归属 1对1 + 类型 1v1商品 + 除全国班外的所有分校 + 高中部 +
  （短期班 / 活动类 / 诊断类）；有「一键开关 + 范围改配」能力。

**注意「1对1」不等于「只有 1人班」**：1对1 业务线下还有 **8人班**——班课侧给 1对1 新增过二级类目
「**托管AI**」，该类目**分类只能选「8人班」**（反向限制：业务线=1对1 且 分类≠8人班 时，
**禁止使用托管AI类目**）。所以「1对1 业务归属的班」人数可能是 **8 人**，授课类型是**托管**
（课态=学习空间，见 [[coursestate-mapping]]）。

**1对1 商品**侧则相反：只能选 **1人班 / 彼芯托管 / vip托管**。

**「关闭」和「下架」不是一回事**（分校最容易搞错）：不想再售卖商品时应当**下架**；
线上出过 3 起**误用「关闭」**导致「商品后续服务无法正常进行」的事故，因此 1对1 商品列表
**点「关闭」时会实时校验**——**已报名额 > 0** 或**存在绑定关系的未结课班课**时直接拦截，
提示「**该商品已有报名学员，无法关闭**」。

报名失败时的错误码含义另见 `one-on-one-booking-error-codes`——按文案字面理解会踩坑。

## 判据

用户报「买不了 / 加了购课单结算时报错」时：

1. 先看是否踩了合并规则：**未被订单侧配置放开的组合**会被拦（提示「您选择的班级不允许合并下单，请重新选择」）、
   **长期班混短期班**也会被拦——注意**「跨业务线」本身 2026-08 起已部分放开**（国际、素养、高中班课＋1对1），
   不要再把它当成必然被拦的原因；
2. 看是否超过 20 个的上限；
3. 提示「课程已失效」说明资源校验失败（`去结算` 时会请求教学确认资源有效性），
   需要重新选课——不是加购丢了。

## 例外

- **C 端当时还不支持「插班报」**：现状是**用户只能购买「未开课且满足首课时间等售卖要求」的整大期**，
  一旦错过就得**等下一个大期**（教师时段利用率也会因此变乱）。2026-07 先给**盘古等内部售卖平台**
  做了「**一个大期内允许插班报**」的紧急支持——**APP 等 C 端要等业务提需后再跟进**，
  而且**只针对高中部**（初中部与全国班暂不推广）。
  **插班报能买多少课次按授课类型分**（大学生业务线的口径）：**在线课、自学课后置排课**
  插班报**只能买全部课次（含回放）**；**其余授课类型（含面授）**插班报**只能买剩余课次**；
  **两种情况都不弹窗让用户选**。**退班重报**同此逻辑。
- **订单页的课次数文案在 2024-06 统一改过**：**所有含「剩余」的表述都去掉了「剩余」**——
  因为「剩余」不适配**分期购买、先缴一期**的场景。现在看到的是：

  | 场景 | 文案 |
  | --- | --- |
  | 买回放课 ＋ 剩余直播课 | 「课程共 `k` 讲 · 购买 `a` 讲（含 `n` 讲回放课）」——`a` = **未上课次 ＋ 回放课次总数** |
  | 仅购买剩余课次 | 「课程共 `k` 讲 · 仅购买 `m` 讲」——`m` 取**本次报名的总课次数** |
  | 课前报、买全部课次 | 「课程共 `k` 讲」（不变） |
  | **1对1 ＋ 报名类型 = 加课** | 「**购买 `x` 讲加课课次**」（`x` = 加课课次数） |

  同期**取消了「大学生」在这段逻辑里的特殊判断**。

- 本期**只在 APP 支持**，小程序不支持；
- 商品范围只有**非长期课**；
- 预课表「不锁时段」意味着加购不等于占位，别人可能先下单占走。
