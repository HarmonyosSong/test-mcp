# 课态（班级卡片上的标签）

## 事实

**「课态」是班级卡片上的那个标签**（家长能直接看到「学习空间」这几个字），
由「**授课类型 ＋ 业务归属**」共同决定——**同一个授课类型，业务归属不同，课态就不同**：

| 授课类型 | 业务归属 | 课态 |
| --- | --- | --- |
| 托管 | **彼芯** | **托管** |
| 托管 | 高中 / 大学生 / 素养 | **学习空间** |
| 托管 | **1对1 - 8人班** | **学习空间** |

**「托管课态」这个说法有歧义**（文档里两种用法混着出现）：

- **狭义**：课态这个字段的**值 = 托管**——**只有彼芯**的托管班是这个值；
- **广义**：口语指「**托管班的课态**」——高中 / 素养的这些，值其实是**学习空间**。
  例：电子合同文档里写的「托管课态（高中 / 素养在用）」，指的是**学习空间**。

所以看到「托管课态」，**先确认是哪一层意思**，否则会去错误的取值里找。

## 客户端字段（代码锚点）

课态在客户端**不只一套字段名**，按页面分流：

| 场景 | 文件 | 字段 |
| --- | --- | --- |
| 学习页 / 日历 | `XesStudy/src/main/ets/components/end/bean/ClassBean.ets` | `tagId`（课态 id）、`tagName`（课态名称）、`tagNameLength` |
| 订单 / 售后 | `XesOrder/src/main/ets/components/orderBusiness/Model/OrderModel.ets`、`OrderQueryStateModel.ets` | `tagId` / `tagName` |
| 跨报 | `XesOrder/src/main/ets/components/crossReport/viewModel/CrossReportViewModel.ets` | `tagId` / `tagName` |
| 转班选课 | `XesCourseCenter/src/main/ets/courseAdjustment/selecNewCourse/model/CCInfoModel.ets` | `categoryType`（课态值）/ `categoryName`（课态名称） |
| 班级搜索 | `XesCourseCenter/src/main/ets/components/viewmodel/ClassSearchPage.ets` | `categoryName`（课态名称，注释："如卡片需要 label，则用这个字段"） |
| 标签渲染 | `XesCommonUI/src/main/ets/components/card/XesCardTitleComponent.ets`、`XesOnlyTitleHighLightComponent.ets` | 注释即「课态标签」 |

**已知的取值**（都是注释里零星写的，不完整）：

- 跨报页的 `tagId` 注释：`1线下小班、2线下、3线上小班、4线上`；
- 转班里 **`categoryType === 16` 被当成自学课**处理
  （`CourseAdjustmentCell.ets`：`selfStudyType = ... categoryType === 16 ? 1 : 0`）。

**业务代码里出现的枚举值**（比客户端注释更硬，可作为交叉验证）：

| 值 | 含义 | 出处原文 |
| --- | --- | --- |
| **`19`** | **课态 = 学习空间** | 「**课态=19 或 业务归属=彼芯**」→ 班级详情页教师人头**不可点击** |
| **`9`** | **业务归属 = 彼芯** | 「**业务归属=9 彼芯** 且 **课态=19 学习空间**」→ 班级列表页教师人头不可点 |

也就是说「**彼芯 = `9`、学习空间 = `19`**」——排查时可以直接拿这两个数去对服务端下发值。

> ⚠️ **但这组条件本身不自洽，引用时要小心**：需求原文写的是
> 「**业务归属=9 彼芯** 且 **课态=19 学习空间**」——按本页上面的矩阵，
> **彼芯班的课态值是「托管」而不是「学习空间（19）」**，这个 AND 条件在彼芯班上**永远不该成立**。
> 两种可能：**要么 `19` 不是学习空间**（那本页的取值标注要改），
> **要么原文这里把"彼芯"和"学习空间"两组班写混了**。
> **在回查业务代码确认之前，不要拿「19 = 学习空间」去核对彼芯班级的服务端下发值。**
>
> **已做过的代码核对**：「`学习空间`」中文、以及 `9` / `19` 这两个数字**在客户端全部零命中**
> ——它们是**服务端下发的值**，客户端只接不认，**无法用客户端代码交叉验证**。
> （可比对的是另一个：**课态 `16` = 自学课**在客户端有两处独立注释印证
> ——`CourseAdjustmentCell.ets` 与 `ClassItem.ets` 都写了 `tagId === 16` 走自学课样式。）

**注意两个页面的判断条件并不一样**（这是"同一个老师，这里能点那里不能点"的原因）：

| 页面 | 条件 | 逻辑 |
| --- | --- | --- |
| **班级列表页** | `业务归属 = 9` **且** `课态 = 19` | **AND**（两个都满足才不可点） |
| **班级详情页** | `课态 = 19` **或** `业务归属 = 彼芯` | **OR**（满足一个就不可点） |

**注释本身不一致，别按名字猜**：`categoryTypeName` 的注释是「**授课类型**」，
而 `categoryType` / `categoryName` 在转班模块注释是「**课态**」——同一前缀，两个含义。

## 判据

用户问「这个标签是什么 / 为什么显示学习空间」时：

1. **先看授课类型是不是托管**——托管班才有「托管 / 学习空间」这两种课态；
2. **再看业务归属**——彼芯显示「托管」，高中 / 素养 / 1对1-8人班显示「学习空间」；
3. 这不是配置错误，标签由**服务端按上述两个维度下发**；
4. 要改代码，**按页面去找对应字段**（学习页是 `tagName`，转班是 `categoryName`），
   搜「课态」中文能找到注释，搜「学习空间」**搜不到**。

## 例外

- **「学习空间」「托管AI」在客户端零命中**——中文名称由服务端下发，客户端只存 id 与显示名；
- 课态的**取值表没有单一出处**（注释散落在多个文件），以服务端枚举为准；
- 「**学习空间 = 托管**」这个对应关系只说对了授课类型，没说业务归属（见上表）。
