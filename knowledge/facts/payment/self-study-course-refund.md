# 自学课的退费规则

## 事实

**授课类型 = 自学、排课策略 = 后置排课**的课程，能否在 C 端退费**取决于解锁规则**：

| 解锁规则 | 能否 C 端退费 |
| --- | --- |
| **一次性解锁全部课次** | ❌ **仍不允许**——点确认退款会 toast「该自学课暂不支持退费，如有疑问请联系顾问或客服」 |
| **按照规定时间解锁** | ✅ **允许**，按解锁时间判断可退部分 |

**页面上的表述差异**（自学课适配）：

- 班级卡片的「上课时间」显示为 `{解锁规则} · n个月内有效`，n 取自班课系统设置的课程有效期；
- 退费信息里的「当前未上课次」显示为「**当前未解锁课次**」，取的是**未解锁的课次数**（即应退课次数）。

背景：这类课主要面向高中竞赛的高端家长，此前**所有自学课都不支持退费**，对运营和家长体验都有影响，
后来才按解锁规则放开。

代码位置（鸿蒙侧）：

| 环节 | 文件 |
| --- | --- |
| 自学课类型与进度 | `XesStudy/src/main/ets/components/end/bean/ClassBean.ets`（`是否自学课`、`自学课学习进度`） |
| 解锁日期分支 | `XesStudy/src/main/ets/components/viewModel/NewCalendarViewModel.ets`（`/* 自学课 14、15 解锁日期 */`） |
| 退费申请页 | `XesOrder/src/main/ets/components/refund/RefundApply.ets` |

## 判据

用户说「自学课退不了 / 提示该自学课暂不支持退费」时：

1. **先确认解锁规则**——**一次性解锁的不给退**（设计如此），按时间解锁的才能按进度退；
2. 「应退课次数怎么算」→ 看**未解锁的课次数**（页面上叫「当前未解锁课次」）；
3. 提示语「该自学课暂不支持退费…」是**有意拦截不是系统错误**。

## 例外

- 规则只覆盖**后置排课**的自学课（当时无前置排课）；
- 交易退费系统同期做了支持，但 **C 端可退性以解锁规则为准**。
