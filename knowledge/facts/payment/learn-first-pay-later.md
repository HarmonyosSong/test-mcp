# 先学后付（学习模块侧）

## 事实

素养科思业务的「**先学后付**」模式：用户报名后**先学 3 讲次**，再决定是否付费。

**前 3 讲次是关键分界线**：

| 状态 | 行为 |
| --- | --- |
| 前 3 讲次、**未撤单**（未缴费） | **等同于正常报名缴费**——成长页的装扮商城、形象、金币与彼芯币都正常展示 |
| 前 3 讲次、**已撤单**（未缴费） | 视为**未报班未缴费**，不再计入报名查询范围，课程不展示 |

**两条功能差异**（都在「学习二级页」）：

1. **调课**：前 3 讲次（缴费前）**屏蔽调课功能**；
2. **云学习任务**：前 3 讲次正常推送、可正常作答；**撤单后不再展示**，无法继续使用。

## 判据

用户说「为什么不能调课」时：

1. **先确认是不是先学后付的前 3 讲次且未缴费** —— 是的话调课**本来就被屏蔽**，不是故障；
2. 用户说「云学习任务没了」→ 查是否**撤单**（未缴费撤单后课程与任务一起消失）；
3. 用户说「金币 / 装扮不对」→ 未撤单期间应与付费用户一致，不一致才是问题。

## 例外

- ⚠️ **和「先满意再缴费」到底是不是一回事，需要人工确认**（本条的旧说法"两者完全不同"**证据不足**）：
  对方条目写的是"T6 新分校"的 3 讲体验课（见 [[trial-class-pay-after-satisfaction]]），
  但**它 1.0 的来源文档标题恰恰是《【260120】**科思**-先满意再缴费1.0》**、
  打标学科是「**科学思维**」（即科思），**上线日期与本条的 2026-01-20 完全相同**，
  aliases 里也都有「先上课后付费」。
  **两者很可能是同一业务模式的两侧文档**（本条讲**学习模块侧**的行为，那条讲**交易侧**的准入与开关），
  **也可能不是**——排查时按「用户描述的是学习模块现象，还是交易/报名现象」分流，
  **别把它们当成互不相干的两件事**；确认前不要引用本条去否定对方；
- 本条只覆盖**学习模块与课后成长模块**的兼容行为，订单 / 支付侧的规则另算。
