# 用户怎么说 ≠ 云学习叫什么

排查云学习问题的最大摩擦不在技术，在**对不上词**。用户、云学习前端、xesapp 容器三方对同一件
事各有各的称呼，而知识库和代码只认后者。

这条知识解决的是"用户的原话找不到对应实现"，它不解决技术问题本身。

## 对照表

| 用户 / 一线支持怎么说 | 云学习侧怎么说 | 站点 / 模块 |
| --- | --- | --- |
| 语音评测、绘本评测、朗读打分、跟读评分 | 口语岛、语音测评、我的作品 | `english-oralisland-fe` |
| 磨耳朵、听音频、听绘本 | 磨耳朵、音频播放 | `english-oralisland-fe`（同一站点，不同入口） |
| 英语图书馆、绘本馆 | 英语图书馆 | `english-library-fe` |
| 云听课、听直播课 | 云听课 | `chinese-library-fe` |
| 背单词 | 背单词 | `recite-word` |
| 识字、学词、认字阅读 | 识字阅读、学词 | `learn-word-fe` |
| 任务、作业、答题 | 任务答题 | `taskanswer-fe` |
| 积分卡、小星星、奖励 | 积分卡 | `points-card-fe` |
| 成长、首页 | 成长首页 | `grow/home` |

## 判据

**用户用了对照表左列的词，就意味着他要的东西可能在中间列的实现里**。检索知识库时两边都要试：
用用户原话找现象条目，用云学习侧的词找实现。

**用户描述里带"绘本"两个字不代表和阅读有关**。这个词在用户嘴里泛指整个英语学习模块，包括
语音评测、磨耳朵、图书馆——**它区分不了任何一条链路**，不要拿它当筛选条件。

**真正有区分力的是动作**：朗读 / 听 / 背 / 认字 / 看直播。动作对上了，链路才对得上。

## 注意

- 面向一线的回复必须用**用户自己的词**。"口语岛 JSBridge 回调异常"对用户没有意义，
  他需要知道的是"你的朗读评分卡在哪一步"。
- 术语差异不是沟通问题而是**检索问题**：按用户原话去查知识库或代码，命中率很低；先翻译，
  再检索，是这一步的标准做法。
- 这条对照表会随产品改版过期。发现某个词查不到东西时，先怀疑是不是又改名了。
