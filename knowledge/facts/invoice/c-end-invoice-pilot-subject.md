# C 端开票：试点主体与按钮展示规则

## 事实

重庆税务局要求自动开票，试点主体是「重庆市沙坪坝区学而思益慧科技培训有限公司」。
C 端开票按钮的展示条件是：**报名包含试点主体课次 且 已到开课后次月**。

各场景下 C 端的表现（来自需求文档的场景表）：

| 场景 | C 端表现 |
| --- | --- |
| 报名试点主体，未发生调课 / 转班 / 退费 | 开课前及开课当月**无法开票**；开课后次月自动开一张红票 |
| 报名试点主体，**开课前**整班退费 | 进入退费班级，**无查看发票按钮** |
| 报名试点主体，**开课后**整班退费 | 开课后次月按已刷课时自动开一张红票 |
| 报名试点主体，开课前转班到非试点主体 | **不展示开票按钮，也不开票**（改由 B 端盘古组件开票） |

新链路的限制：**不支持专票、不支持多报名合并开一张、不支持一报名拆多张**。

## 判据

用户问「为什么看不到发票 / 开不了票」时：

1. 先确认报名是否包含**试点主体**的课次——不包含的走原有链路，规则不同；
2. 再看时间：**开课前和开课当月本来就不能开**，要等到开课后次月；
3. 退费班级**没有查看发票按钮**是设计如此，不是按钮丢失；
4. 要专票、或要合并 / 拆分申请的，新链路都不支持。

## 例外

- **当前客户端代码里没有任何开票实现**（见下），所以「按钮没出现」在现状下不是客户端 bug；
- 1 期只在 B 端做屏蔽（试点主体开票由顾问 / 客服提交 BPM 流程线下开），2 期才给 C 端；
- 走线下 BPM 开的票 B 端不支持查看；线下开票在培优系统无留存记录，理论上可重复开票（文档已记为已知风险）。
