# 课堂人脸采集与免密登录授权

## 事实

课堂应用会采集学员人脸信息，用于**免密登录**、积分消费等需要强校验身份的场景（省去输账号密码）。
**必须先经家长授权**，课堂才会采集。

**做这件事的两个动机**（文档明写）：**眼前**是用刷脸**省掉输账号密码**、让流程轻量化；
**未来**还想解决「**素养 ics3.0 课间学生积分盗刷**」的问题（等素养接入人脸识别以后）。

- **范围**：彼芯（初中）与 1对1（初高中），试点先从北分开始；
- **授权入口**（两条）：
  - **APP**：我的 → 设置 → 权限设置 → **学生端免密登录**；
  - **H5**（暑期推广期主用）：老师通过**企微**发送的微信消息里的链接 → 打开营业厅小程序的
    H5 授权页，登录后可查看 / 修改**关联学员**的开关状态。
    推广期以**老师触达**为唯一方式（班级群或好友侧边栏的一键发送入口）；
- **通知方式**：APP-push + 短信。push 标题「免密登录授权提醒」，正文
  「开启免密登录授权，告别繁琐密码输入，让孩子上课更快捷！……」，点击跳到开关详情页；
  推送按**学员编号去重，每个学员只发一次**；
- **我的消息**里会新增一种卡片：`62. 课堂人脸授权提醒`。

**关闭授权后的行为**——代码里的原文文案（比 PRD 更细）：

> 关闭授权后学而思将**删除相关数据**，**登录入口仍会显示，但无法使用**免密登录。

即「删数据 / 入口仍在 / 不能用」是**三件不同的事**，不要当成一个来判。

## 判据

用户问「为什么要采集人脸 / 免密登录怎么关了」时：

1. 人脸数据用于**免密登录**（及积分消费等强校验场景），采集前必须有家长授权；
2. 用户说「关了授权还能看到登录入口」→ **正常**：入口常驻，只是点了不能用；
3. 用户问「关了还留着我的数据吗」→ 代码文案写明**关闭会删除相关数据**；
4. 收到「免密登录授权提醒」但没印象 → 同一学员只推一次，可能是另一位家长收到的。

## 例外

- 试点范围由课堂服务定义，**不是全量开通**——没有这个开关的学生可能只是不在试点内；
- 需求原文的版本范围写「iOS & Android & 鸿蒙」，鸿蒙侧已核对有实现。
