# 扫一扫：支持的端与 http 拦截

## 事实

**各端支持情况**（截至文档记录，补版时间见备注）：

| 应用 | 扫一扫 |
| --- | --- |
| 学而思 APP | iOS & Android & 鸿蒙 ✓ |
| 学而思 HD | iOS & 鸿蒙 ✓；**Android 自 V5.102.1 起补齐** |
| 学家云 APP | Android（同期补齐） |
| 学家云 HD | Android（同期补齐） |

**扫码能力**：

- 支持**积分卡**扫码；
- 支持扫码后由服务端解析二维码并跳转；
- 支持**教材上印刷的配奇音视频资源**二维码（此前只支持微信扫，因为微信对链接有封禁风险，
  才开放了 APP 扫码）；
- **不支持**从本地相册选图片扫码。

**http 地址会被拦截**（全系统安全整改的产物）：

扫到的跳转地址是 **http 协议**（未加密）时，**服务端不下发链接**，客户端 toast
「**已拦截未加密的跳转地址（http协议）**」，超时后提示消失且**不跳转**。

> 背景：此前发生过「学习机因 http 跳转地址被劫持、导致学员访问不良内容」的事件，
> 之后所有系统对 http 跳转统一做升级或拦截。

**展示规则**：学而思 APP 的扫一扫**常驻展示**；学而思 HD 是**特定分校才展示**（服务端控制）。

代码位置（鸿蒙侧）：

| 环节 | 文件 |
| --- | --- |
| 扫一扫页面 | `XesMine/src/main/ets/components/exchangeCourse/ScanCodePage.ets` |
| 我的页入口 | `XesMine/src/main/ets/components/mainpage/MineTabViewModel.ets`、`MoreButtonsContainer.ets` |
| Pad 入口 | `XesMine/src/main/ets/components/pad/view/PadMineViewHeader.ets` |

## 判据

用户说「扫码扫不出来 / 扫了打不开」时：

1. **先看提示文案**——若是「已拦截未加密的跳转地址（http协议）」，那是**安全拦截不是故障**：
   二维码指向 http，需要提供方换成 https；
2. **问是哪个端**——HD / 学家云的 Android 是后来才补齐的，老版本可能没有扫一扫入口；
3. **问码的来源**——教材上的配奇资源码、积分卡、普通二维码走的解析路径不同；
4. 用户说「想从相册选图扫」→ **不支持**，只能实时扫。

## 例外

- 拦截提示由**服务端触发、不下发链接**，所以客户端搜不到这句文案（已核对零命中）；
- HD 的扫一扫**不是所有分校都有**，看不到可能只是没开；
- 入口在**我的**页面，不在首页。
