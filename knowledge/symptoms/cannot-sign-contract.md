# 付款页看不到合同 / 协议

## 通用原因（三端共有）

1. **这个班没配电子合同，走的是协议** —— 合同与协议**互斥展示**：**配了合同就不展示协议**（这条在服务端）。
   但**反过来不成立**：没配合同时**协议不一定出现**——客户端只是渲染
   `requestPromptInfo` 返回的 `districtsAggr`，**返回空就不显示，且「空」本身不等于 bug**。
   见 [[order-contract-agreement-sources]]；
2. **配了合同但模板未「生效」** —— 未生效的模板不会被展示，表现和没配一样；
3. **课态本来就不支持签约** —— 托管课态在 2026-06 之前因合规不支持，之后才放开；
   所以**那个时间之前的托管课订单没有合同是预期行为**，见 [[order-contract-agreement-sources]]；
4. **合同被作废了** —— 退费、转班、换商品都会触发合同作废；教学点切换会触发补签。
   见 [[contract-void-resign-scenarios]]。

## 区分它们需要什么

按顺序问 / 查（每一步都能砍掉候选）：

1. **是从来没有，还是以前有现在没了？**
   - 从来没有 → 走 1 / 2 / 3（配置或课态）；
   - 以前有 → 走 4（作废场景）；
2. **用户近期退费 / 转班 / 换商品了吗？** —— 是，则作废是预期的，不是 bug；
3. **同一个班的其他家长能看到吗？** —— 别人也没有 → 班级级配置问题；别人有 → 个例。

## 注意

- 服务端的开通范围是**按规则写死的**，客户端不做互斥判断——别指望在鸿蒙代码里找到
  "为什么没展示"的逻辑；
- 配置状态与作废记录都要人工去班课系统的「合同与协议管理」查，agent 查不到；
- 客户端侧能自查的只有一处：合同是否后置到支付环节，见
  `ConfirmOrderPage.shouldMoveContractSignToCashier()`。
