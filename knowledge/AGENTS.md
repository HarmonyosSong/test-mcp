# 知识库维护约束

修改前阅读 [README.md](README.md) 的业务域分工和 [_schema.md](_schema.md) 的字段约束。
入库内容仍遵循 [筛选条件](../docs/decisions/0001-knowledge-base-selection.md)。

## 新增或修改条目

1. 先按用户用词、别名和业务语义查找已有条目。能补充现有条目时直接补充，不按产品、端或目录复制事实。
2. 事实放 `facts/<业务域>/<name>.md`，现象放 `symptoms/<name>.md`。业务域分一层，优先复用已有目录。
   新域确有必要时，在同一次修改中更新 README 的目录分工；不要按代码模块名机械拆域。
3. 每条事实只有一个主目录。涉及多个业务域时填写 `domains`，必须包含主目录；`shared` 仅用于真正共用的事实。
   现象可填写多个候选域；未知时省略，不猜测产品、端或业务域。
4. `name` 是全库唯一且稳定的 ID，必须与文件名一致。移动条目时保持 ID，使用 `[[name]]` 跨域引用，禁止路径引用。
5. 补充用户原话 `aliases`、代码或其他证据入口、来源与适用范围。目录和业务域不能替代这些检索与验证信息。
   未核实内容按既有规则标为线索，不能因为重新分类而提升可信度或刷新人工验证日期。
6. 在仓库根目录执行 `make knowledge-validate`，修复错误并说明剩余告警。分类迁移还要确认条目没有丢失、引用仍能解析。

## 检索约束

- 业务现象优先查现象知识，未命中或匹配较弱时查事实；明确技术线索可以直接查证据。
- 候选业务域和 `shared` 仅在同等文本分数下优先；其他域持续参与检索，禁止改为硬过滤。
- 无有效结果时取消业务域偏好，并根据已知术语调整查询；业务域未知时全局检索。
- 修改加载或排序机制时验证：跨域引用、跨域强匹配、错误分类的回退、共用事实与无关查询不误命中。
