# 查学员信息（轻量闭环，可多路复用）

**用途**：查学员档案 / uid / 近 3 天登录设备。可单独收尾，也可在故障排查里先 load 本技能取人，再 load 排查类 Skill，**复用本轮已查到的学员编号 / uid**。

有学员编号则先查档拿到 uid；**只要本轮已有 uid，就必须经 log-mcp 查近 3 天登录/设备线索再写设备段**（执行上不是「只查档案、不查设备」）。

- **本轮只要信息、不排障**：查完按下方「信息查询」模板收尾；不要读源码、不要 `consult_compass`、不要套故障「问题原因」模板。  
- **本轮要排障**：本技能只负责取人/设备线索；取到后继续排查类 Skill，最终回答用故障判定锚点，不要用「判定：信息查询」收尾。  
- log-mcp 工具细节以本轮已挂载工具为准；需要完整日志纪律时可再 `load_skill("query-platform-logs")`。

## 识别标识

- 文案带「学员编号」→ 学员编号（card）。
- 文案带 `uid` /「UID」→ uid。
- 纯数字无标签：`≥11` 位当学员编号（如 `184010299547`）；更短当 uid（如 `5570040`）。
- **既没有学员编号也没有 uid**：直接追问「请补充学员编号或 uid」，不要猜、不要空查。

## 流程

1. **有学员编号**：调用 `lookup_learner` 取档案（uid、姓名、年级等）。拿到档案里的 uid 后再查设备。
2. **只有 uid**：不调用 `lookup_learner`。用该 uid 经 log-mcp 查设备。日志命中里若带出姓名等字段则一并写出；没有就只报设备和端侧线索。
3. **设备查询（强制，走 log-mcp，默认 3d + 双侧）**：拿到 uid 后本轮必须调用 **log-mcp** 再写设备段，不要自己编登录/设备结论。  
   - **推荐**：`search_both_logs(time="3d", query="<uid>", cloud={})`（日志中心与云日志**两侧并行**）。  
   - 若先 `cloud_search`：同一轮、同一 `3d` 窗内**必须再查日志中心**（`query` 或补一次带 logcenter 的 `search_both_logs`）；禁止只查一侧就下设备结论。  
   - `query` 只传 **uid 裸数字**（如 `5570040`）；禁止学员编号/card，禁止 `uid:…` / `card:…` / `| select …`。  
   - 本轮没有 log-mcp 工具（未挂载）→ 按第 6 条降级，不要假装查过。
4. **近 3 天无命中**：仅在本轮已 **双侧覆盖**（`search_both_logs(..., cloud={})`，或 `cloud_search`+`query`）且 `time=3d`（或用户要求的更宽窗）结果确实无命中时，才写「最近 3 天未登录」。
5. **未调 log-mcp 前禁止**：不得写「最近 3 天未登录」「暂无登录/设备线索」等空结论；也不得用上一轮或其他学员的日志结果顶替本轮。
6. **log-mcp 不可用**：有档案则只回档案，并说明「设备侧暂不可查」；只有 uid 且日志不可用时如实说明缺口。此情形不要写成「未登录」。
7. **本轮已有设备结论**：后续故障排查 Skill **复用**，禁止无新条件地重复同窗双侧全量。

## 输出

**仅当本轮只要学员信息、无相关继续排障时**：直接按信息查询模板返回内容（有什么填什么，没有的行省略）。  
**若本轮继续故障排查**：把档案/uid/设备线索留给后续排查 Skill，按故障判定锚点收尾。

信息查询模板：

```text
【学员信息】
学员编号：…
UID：…
姓名：…
年级：…
城市：…（根据得到的areaCode自行映射为中文城市名）
其他：…（接口或日志里多出来的非敏感字段可写；手机号若出现须保持脱敏形态）

【最近登录设备（近3天）】
- …（端 / 版本 / device_id / 最近出现时间；或：最近 3 天未登录）
```

缺标识时正文写需要补充学员编号或uid。
