# 查学员信息（轻量闭环）

用户只是确认学员信息 / 查用户档案 / 查最近登录设备时使用本技能。
不要加载排查类 Skill，不要读源码，不要 `consult_compass`，不要套故障「问题原因」模板。

## 识别标识

- 文案带「学员编号」→ 学员编号（card）。
- 文案带 `uid` /「UID」→ uid。
- 纯数字无标签：`≥11` 位当学员编号（如 `184010299547`）；更短当 uid（如 `5570040`）。
- **既没有学员编号也没有 uid**：直接追问「请补充学员编号或 uid」，不要猜、不要空查。

## 流程

1. **有学员编号**：调用 `lookup_learner` 取档案（uid、姓名、年级等）。再用返回的 uid 调 log-mcp 查近 7 天登录线索。
2. **只有 uid**：不调用 `lookup_learner`。直接用该 uid 调 log-mcp 查近 7 天。日志命中里若带出姓名等字段则一并写出；没有就只报设备和端侧线索。
3. **设备查询**：使用本轮已挂载的 log-mcp 工具即可（如 `search_both_logs` / `query` / `cloud_search` 等），时间窗近 7 天，按 uid 过滤。不指定必须某一侧引擎。
4. **近 7 天无命中**：写「最近 7 天未登录」。
5. **log-mcp 不可用**：有档案则只回档案，并说明设备侧暂不可查；只有 uid 且日志不可用时如实说明缺口。

## 输出

首行必须是：`判定：信息查询`

随后用信息模板（有什么填什么，没有的行省略）：

```text
判定：信息查询

【学员信息】
学员编号：…
UID：…
姓名：…
年级：…
其他：…（接口或日志里多出来的非敏感字段可写；手机号若出现须保持脱敏形态）

【最近登录设备（近7天）】
- …（端 / 版本 / device_id / 最近出现时间；或：最近 7 天未登录）
```

缺标识时的追问也以 `判定：信息查询` 开头，正文只写需要补充学员编号或 uid。
